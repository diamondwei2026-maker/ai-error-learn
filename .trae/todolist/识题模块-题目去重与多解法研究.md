## 核心结论

1. **当前状态**：识题接口完全无去重，存储层按客户端生成的 ID 唯一，不感知题目内容
2. **MVP 建议**：做轻量级精确哈希匹配（content_hash 字段 + normalize 标准化 + 客户端温和提醒），投入小、见效快
3. **多解法问题**：拆分为 3 种场景——独立错题（应保留）、关联笔记（后期功能）、纯粹重复（去重解决）
4. **跨用户去重**：个人错题本按 user_id 隔离，MVP 不需要
5. **进阶方案**：题量 > 500 题时考虑 embedding + HNSW 向量索引做语义匹配

## 推荐优先级

- **P0**：Question 类型加 contentHash 字段 + normalizeForHash() 函数
- **P1**：客户端创建题目前查本地哈希表，命中弹温和提醒
- **P2**：服务端 sync 接口加被动查重日志（不拦截）
- **P3**：等真实数据驱动再考虑语义相似度
