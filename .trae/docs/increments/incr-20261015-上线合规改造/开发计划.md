**综合评级：中等** —— 跨模块但**纯增量**，无数据模型变更、无核心业务逻辑变更、**完全可回滚**。

**归档方式建议：`/plan`**（普通增量，文档存入本 increments 目录，**不修改** `.trae/specs/mvp-reverse-docs/`）。
> 说明：按项目规则「跨模块」字面可归 `/spec`。但本次不触碰数据模型与核心链路逻辑，且回滚成本极低，故建议 `/plan`。**若你要求按高风险走 `/spec`，我改产出 `spec.md` + `tasks.md` + `checklist.md`。**

### 风险清单

| # | 风险 | 等级 | 触发条件 | 影响 | 应对措施 |
| --- | --- | --- | --- | --- | --- |
| R1 | **启动被阻断** | 中 | `privacyService.init()` 抛错未捕获 | 小程序启动异常 | `app.tsx` 内 `init` / `checkOnLaunch` 全包 `try/catch`，失败仅记日志、不阻塞启动 |
| R2 | **隐私接口永久 pending** | **高** | `onNeedPrivacyAuthorization` 回调触发后未调用 `resolve` | 拍照/头像/昵称**卡死无响应** | 「同意」「拒绝」**两条分支都必须 `resolve`**；拒绝走 `resolve({ event: 'disagree' })` |
| R3 | 同意按钮校验失败 | 中 | 用普通 `View` 冒充按钮，或 `buttonId` 不匹配 | 授权不生效，接口仍被拦截 | 必须用原生 `<Button id="agree-privacy-btn" openType="agreePrivacyAuthorization">`，`resolve` 时传同一 `buttonId` |
| R4 | **挂载点遗漏** | 中 | `quiz` / `edit` 页有多个 `return` 分支，漏挂 | 该状态下弹层不出现 → 授权缺口 | 按 **9 个 return 分支**逐一挂载并核对（见 §2.3） |
| R5 | H5 端报错 | 中 | Taro 隐私 API 仅 `weapp` 支持 | `build:h5` 报错 | `isWeapp` 判定，非 weapp 直接 noop |
| R6 | 昵称静默降级 | 中 | `<input type="nickname">` 未同意时不触发 `onNeedPrivacyAuthorization` | 用户以为填了昵称，实则降级为普通文本 | 昵称 `onFocus` 主动调 `requirePrivacyAuthorize()` |
| R7 | 重复弹层 | 低 | 多隐私接口并发触发 | 弹层叠加 | `privacyStore` 单例控制 `visible`，已打开则复用 |
| R8 | 后台未声明隐私类型 | **高（平台侧，非代码）** | 未配置《用户隐私保护指引》 | `errno 112` / `appid privacy api banned`，接口被禁用 | **你方**在 MP 后台声明（头像、昵称、微信登录标识、相机/相册）；代码侧保证流程正确 |
| R9 | 拒绝后 10 秒内重复调用 | 低 | 微信限制：距上次拒绝不足 10 秒不再弹窗 | 报错 103/104 | 调用侧友好提示 + 重试引导，不静默卡死 |

## 三、编码步骤

### 阶段 A · 隐私基础设施

- **A1** 新建 `store/privacyStore.ts`（zustand 单例：`visible` / `contractName` / `resolveRef`）
- **A2** 新建 `services/privacyService.ts`
  - `init()`：`Taro.onNeedPrivacyAuthorization((resolve, info) => { store.open(resolve) })`
  - `checkOnLaunch()`：`Taro.getPrivacySetting()` → `needAuthorization === true` → `store.open()`
  - `openContract()`：`Taro.openPrivacyContract()`
  - `requireAuthorize()`：`Taro.requirePrivacyAuthorize()`（供昵称 `onFocus` 用）
  - 全部 `isWeapp` 守卫 + `try/catch`
- **A3** 新建 `components/PrivacySheet`（tsx + scss，复用 LoginSheet 面板规范）
  - 同意按钮：原生 `<Button id="agree-privacy-btn" openType="agreePrivacyAuthorization">`
  - 拒绝按钮：`AppButton variant="text"`
  - 「查看平台隐私协议」→ `openContract()`
  - 正文内《用户协议》《隐私政策》→ 跳协议页

**阶段 A 完成即自测**：`npm run build:weapp` 通过。

- **B3** `pages/profile/edit` 昵称 `Input` 加 `onFocus` → `requireAuthorize()`

## 六、与上游方案的差异修正（3 处）

| # | 上游方案原文 | 修正 | 原因 |
| --- | --- | --- | --- |
| 1 | 「小程序启动 → 主动弹隐私弹层」 | **启动弹层必须非阻断**：提供「暂不授权」，拒绝后不得中断任何非隐私功能 | 违规点是「阻断」；本产品已有游客模式可承接 |
| 2 | 「6 个页面各加一行 `<PrivacySheet />`」 | **实际 9 处挂载点**（6 页面 / 9 个 return 分支） | `quiz` 有 3 个 return 分支、`edit` 有 2 个 |
| 3 | 隐私调用点含 `Taro.login` | **`Taro.login` 不是隐私接口**，实际调用点仅 3 个 | 官方接口清单不含 `wx.login` |
