## 一、需求背景与现状

### 1.1 现状（来自代码勘察）

| 维度     | 现状                                                                                                                                              |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 端形态   | 微信小程序（Taro + React + TS），tabBar 4 项：首页 / 题库 / 刷题 / 我的                                                                           |
| 刷题     | `pages/quiz` 为**随机抽题 + 翻面看答案**，无任何复习计划概念                                                                                      |
| 数据     | 本地 Storage（`q:list` / `q:meta` / `q:schema`）+ 云端 `question_sync` 表（仅文本，字段：`content`/`answer`/`created_at`/`updated_at`/`deleted`） |
| 用户体系 | 已具备：微信登录（openid）→ JWT，`server/app/api/auth.py`、`services/wechat_service.py`                                                           |
| 提醒能力 | **完全不存在**：无订阅消息、无定时任务、无不扰设置                                                                                                |
| 原规划   | 方案设计文档第 13 章将「科学复习引擎」列为中等优先级，注明需定时调度 + 订阅消息                                                                   |

### 1.2 本次增量定位

把「随机复习」升级为「按遗忘曲线到期复习」，并补齐主动触达能力（订阅消息），形成「站内兜底 + 主动提醒」的完整闭环。

---

## 二、研讨结论（已确认口径）

| 决策点   | 结论                                                                                          |
| -------- | --------------------------------------------------------------------------------------------- |
| 提醒渠道 | **小程序内提醒 + 微信一次性订阅消息**（不做短信/公众号/邮件；系统日历列为可选后续项）         |
| 复习节奏 | **1 / 2 / 4 / 7 / 15 / 30 天** 共 6 轮，按题独立排期，每日聚合                                |
| 完成判定 | **翻面即完成**并推进到下一轮，同时提供「记住了 / 没记住」轻量自评；选「没记住」则间隔回退一级 |
| 入口关系 | **只做到期队列**：刷题页不设模式切换控件，无到期题时展示空态；随机抽题不在本期范围            |
| 提醒时间 | **固定每日 20:00** 服务端扫描并聚合下发，每日最多 1 条                                        |

### 2.1 提醒分层策略（核心设计）

```
第 1 层 不打扰：首页「今天该复习 N 道」卡片 + tabBar 红点 + 刷题页默认到期队列
第 2 层 主动触达：订阅消息，每日 20:00 聚合一条，点击直达到期队列
第 3 层 强提醒（后续可选）：wx.addPhoneCalendar 写入系统日历，到点原生响铃
```

强制规则：

1. **21:00–8:00 静默**，不发送任何消息。
2. **每日上限 1 条**，多题必须聚合，禁止逐题推送。
3. **连续 3 天未复习 → 自动降频至每周 1 次**；恢复复习后立即回到每日节奏。
4. 消息点击必须**直达到期队列**，不得只落到首页。
5. 一次性订阅需在复习流程结束时引导补充授权额度（借助「总是保持以上选择」减少弹窗）。

## 三、范围

### 3.1 In Scope

1. 错题增加复习调度字段（本地 + 云端），入库即排期次日到期。
2. 到期判定与轮次推进的**纯函数算法模块**（本地/云端共用逻辑口径）。
3. 首页「今日待复习」卡片 + tabBar 红点角标。
4. 刷题页到期队列（无到期时展示空态），队列内翻面 + 轻量自评。
5. 服务端每日 20:00 定时扫描到期题 → 聚合 → 一次性订阅消息下发。
6. 复习结束页的订阅授权引导。

### 3.2 Out of Scope（明确不做）

- 短信 / 公众号模板消息 / 邮件提醒
- 长期订阅消息（受个人主体类目限制）
- 自定义提醒时间、免打扰时段自定义、多设备推送偏好设置
- 随机抽题 / 随机再练入口（刷题页仅保留到期队列）
- 复习成绩统计报表、掌握度热力图
- 系统日历提醒（列为后续可选项，本次不做）

## 四、边界与异常

| 场景                                  | 处理                                                                            |
| ------------------------------------- | ------------------------------------------------------------------------------- |
| 游客（未登录）                        | 站内卡片与到期队列正常可用；**收不到订阅消息**（无 openid），引导登录后开启提醒 |
| 用户拒绝订阅授权                      | 永久降级为站内提醒，不再反复弹窗纠缠                                            |
| 到期题数为 0                          | 不发送消息；首页卡片显示「今天已复习完」空态                                    |
| 单日到期题过多（>30）                 | 消息文案只报总数，队列按到期时间由早到晚排序，支持分轮                          |
| 云端同步失败 / 离线                   | 站内到期判定以**本地数据**为准，云端仅用于跨设备与推送触发                      |
| 订阅消息发送失败（额度用尽/用户拒收） | 记录失败原因，不重试超过 1 次，不阻塞其他用户                                   |
| 题目被删除                            | 排期一并失效，不再计入到期                                                      |

## 五、技术方案概要

**数据层**：`Question` 增加 `nextReviewAt` / `reviewStage` / `lastReviewedAt`；云端 `question_sync` 表新增同名列（migration + 同步协议兼容，旧客户端字段缺失时按「未排期」处理）。

**算法层**：纯函数 `calcNextReview(stage, rating)`，间隔表 `[1,2,4,7,15,30]` 天；`rating = 没记住` 时 stage-1（最低 1 天），`记住了` 时 stage+1；stage 超过 6 视为「已掌握」，退出队列。

**触达层**：`wechat_service.py` 扩展 `send_subscribe_message(openid, template_id, data, page)`；`server/app/api/` 新增提醒相关接口（订阅状态上报、模板 ID 下发）。

**调度层**：APScheduler 每 5 分钟 tick 一次，命中 20:00 窗口则扫描当日到期用户并聚合发送；单实例部署，暂不引入消息队列。
