首次引导流转（本增量唯一实质改动）

设计说明

本节为原型配套说明，不进入任何界面。本增量无界面视觉改动，页面沿用现有 pages/profile/edit 已确认视觉。

一、页面与状态清单

编号 界面 / 状态 关键模块（自上而下） 与现有系统的关系
① 完善资料（首次登录自动进入） NavBar「完善资料」（带返回）→ 大头像（点击更换）→ 昵称输入 → 底部「保存」 完全复用现有页面，无新增/改动模块
② 完善资料（从「我的」进入） 同 ①，完全一致 现有行为，保持不变
③ 「我的」· 已登录（入口上下文） 头像+昵称+chevron → 退出登录 / 注销账号 → tabBar 现有页面，行为不变

二、交互流转

  • 首次登录：用户在首页或「我的」完成「微信一键登录」→ 若昵称为空且从未引导过 → 自动进入「完善资料」页。
  • 保存：填昵称（可选头像）→ 点「保存」→ 成功 Toast → 返回来路页；此后不再自动引导。
  • 跳过：直接点顶部返回按钮 → 返回来路页；此后不再自动引导（用户仍可从「我的」进入修改）。
  • 常规修改：「我的」→ 点击头像/昵称区 → 进入同一页面（无任何差异）。

三、状态差异说明

  • 首次引导态与常规态为完全相同的页面，无任何视觉/结构差异；本增量的改动只在「登录成功后多一次自动跳转」。
  • 「跳过」由页面已有的顶部返回按钮承担，不新增按钮，界面保持纯净。

四、同类产品参考点（定向调研）

  1. 能力路径唯一：微信已收回 getUserProfile，现仅支持「头像昵称填写能力」——open-type="chooseAvatar" + input type="nickname"，须用户主动提供。（参考：微信官方《获取头像昵称》）
  2. 登录与资料完善分离：主流小程序先完成登录，再单独引导「完善资料」，不把资料授权捆绑在登录按钮上。
  3. 登录后跳转完善资料页：以独立二级页承接，返回即可跳过，是教育/工具类小程序通行做法；不额外造弹层与按钮。
  4. 必须可跳过：微信审核要求资料完善不得强制；本方案以「顶部返回即跳过」满足。
  5. 不得进入即授权：审核驳回「未体验功能即要求授权头像/昵称」，故引导只在用户主动登录后出现。

  • 真实头像/昵称素材：骨架中以灰色占位表示。
