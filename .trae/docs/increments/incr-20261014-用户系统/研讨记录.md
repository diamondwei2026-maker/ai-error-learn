## 二、研讨结论（已确认口径）

### 2.1 范围（In Scope）

1. **微信一键登录**
   - `wx.login` 取 code → 后端 `code2Session` 换 openid → 自建用户 → 签发 JWT（access + refresh）
   - 登录态本地持久化，过期自动续期
   - AppSecret 存后端 `server/.env`，不入仓库、不下发前端
   - 游客模式：未登录可直接使用本地基础功能；**仅「拍照/相册识别（多模态 AI 识别）」需登录**，游客点该入口走登录引导

2. **「我的」Tab 页（一级页面，tabBar 3 → 4 项）**
   - 内容：**头像 + 昵称展示、退出登录、注销账号**
   - **不做**：错题统计、云同步状态、手动「立即同步」、关于、独立「设置」页
   - 完善资料（头像 `chooseAvatar` + 昵称输入）由「点击头像/昵称区域」进入 —— _（据「本次做完善资料」推断，待原型阶段确认）_

3. **完善资料**
   - 用户主动授权头像（`chooseAvatar`）+ 填写昵称（微信新规：不能静默获取，必须用户主动提供）

4. **云同步（用户无感知，自动）**
   - 范围：**仅文本**（题干 / 答案 / 创建与更新时间）；**图片不上云**，预留后续增量
   - 触发：登录后**自动**执行（本地全量 push + 云端增量 pull 合并），无用户可见的同步 UI
   - 冲突：同一条错题按 `updatedAt` **新者优先**覆盖
   - 其他设备拉回的错题**仅有文本、无原图**（已在编辑页/详情页可容忍）

5. **退出登录 / 注销账号**
   - 退出登录：仅清除本地登录态，**本地错题保留**（回到游客态）
   - 注销账号：二次确认后，**删除云端数据 + 清除本地全部数据**，回到初始状态

6. **后端账号服务（新建）**
   - ORM 抽象（SQLAlchemy）+ 开发期 SQLite，上线切换阿里云 RDS，业务代码不动
   - 用户表 / 错题同步表；JWT 签发与校验
   - 新增接口域：`/api/v1/auth/*`、`/api/v1/user/*`、`/api/v1/sync/*`
   - **识别接口补鉴权**（现状无鉴权，属既有风险 §8.2-2，本次一并收敛）

### 2.2 数据层策略（用户指定：给出最具性价比方案）

> 用户目标态：**所有数据最终上云，本地为过渡**；但要求本次走「最具性价比」路径。

**采纳方案：本地为主体 + 登录后自动增量上传（双写），本次不做云优先。**

| 维度     | 本次做法                                                       | 理由                                 |
| -------- | -------------------------------------------------------------- | ------------------------------------ |
| 读路径   | 仍读本地（`storageRepo` 不变）                                 | 页面/组件零改动，风险最低            |
| 写路径   | 本地写入后，登录态下追加云端写入                               | 本地为唯一真实来源，云端作镜像       |
| 登录后   | 自动 push 本地全量 + pull 云端增量 → `updatedAt` 新者优先合并  | 用户无感知，无需同步 UI              |
| 演进路径 | 未来切「云优先」时**只替换 `repo` 层实现**，页面与业务逻辑不动 | 架构解耦已预留，避免本次支付改造代价 |
| 图片     | 不上云（预留）                                                 | 控制成本与复杂度                     |

### 2.3 非目标（Out of Scope）

- 会员 / 订阅 / 微信支付（个人主体不可用）
- 图片上云、对象存储（仅预留接口）
- 密码登录、手机号登录、第三方账号绑定、多账号切换
- 管理后台、运营配置后台
- 推送 / 订阅消息、艾宾浩斯复习引擎
- 「我的」页的错题统计 / 同步状态 / 立即同步 / 关于 / 独立设置页
- 修改主 spec（`.trae/specs/main-system/`、`mvp-reverse-docs/`）
- 前端自动化测试补齐（如需要另行增量）

### 2.4 关键约束与风险（研讨阶段识别）

| #   | 约束 / 风险                                                   | 影响                               | 应对                                                                      |
| --- | ------------------------------------------------------------- | ---------------------------------- | ------------------------------------------------------------------------- |
| R1  | 小程序请求后端需 **HTTPS 合法域名（备案）**，个人主体同样受限 | 云同步与登录真机无法直连家宽局域网 | 开发期内网/局域网联调 + `urlCheck` 关闭；上线前置条件单列，不阻塞本次开发 |
| R2  | 微信 `code2Session` 依赖 **AppSecret**                        | 未配置则登录不可用                 | 缺失密钥不抛错，接口返回明确「未配置」错误码；由用户填入 `server/.env`    |
| R3  | 现有识别接口**无鉴权**，加鉴权会改动现有调用链                | 影响 `recognitionService`          | 影响范围显式列出，前端统一注入 token                                      |
| R4  | 现状 `schemaVersion=1` 且**无迁移逻辑**                       | 新增同步字段可能破坏老数据结构     | 仅**追加可选字段**，不改既有字段语义；同步字段做默认值合并                |
| R5  | 本地「全量读 + 切片」，同步后数据量增长                       | 性能退化                           | 同步走批量接口 + 按 `updatedAt` 增量；分片优化列为后续                    |
| R6  | 头像昵称微信新规                                              | 无法静默获取                       | `chooseAvatar` + `nickname` 输入，用户主动提供                            |
| R7  | 个人主体审核口径                                              | 涉及用户数据收集需隐私合规         | 复用现有《用户隐私保护指引》诉求，列为上线前置项                          |

## 四、原型范围（阶段1 覆盖的增量界面）

仅制作**新增/修改模块**，并体现与现有页面的上下文关系：

1. 「我的」页 —— **未登录态**（引导登录）
2. 「我的」页 —— **已登录态**（头像昵称 + 退出登录 + 注销账号）
3. 完善资料页 —— 头像授权（chooseAvatar）+ 昵称填写 + 保存
4. 登录引导 —— 游客点击「拍照录入」时的登录提示（弹层或页面）
5. 注销账号二次确认弹窗
6. 底部 tabBar —— 3 项 → 4 项（新增「我的」）
