设计说明

本节为原型配套说明，不进入任何界面。阶段1 只表达结构与流转，视觉细节留待阶段2。

一、页面与状态清单

编号界面 / 状态关键模块（自上而下）与现有系统的关系
①「我的」· 未登录NavBar「我的」→ 头像占位+「未登录」→ 主按钮「微信一键登录」→ tabBar新增页面；复用 NavBar / AppButton
②「我的」· 已登录NavBar → 头像+昵称+点击修改（chevron）→ 列表「退出登录」「注销账号」→ tabBar新增页面；行样式参考现有列表卡片
③完善资料NavBar（带返回）→ 大头像（点击更换）→ 昵称输入 → 底部固定「保存」新增二级页；复用 NavBar / AppButton
④登录引导首页底图（变暗）→ 底部弹层：标题+说明+「微信一键登录」/「暂不登录」叠加在现有首页；复用现有 ActionSheet 弹层观感
⑤注销二次确认「我的」底图（变暗）→ 居中弹窗：警示图标+标题+说明+「取消」/「确认注销」直接复用现有 ConfirmDialog

二、交互流转

  • 未登录访客：首页 / 题库 / 刷题 / 我的 均可进入；可在「我的」点「微信一键登录」。
  • 受限操作触发登录：游客在首页点「拍照录入」→ 弹④登录引导；点「暂不登录」关闭弹层并留在首页，不阻断其他操作。
  • 登录成功：弹层/页面关闭 →「我的」切到状态② → 后台自动执行一次云端同步（无用户可见 UI）。
  • 修改资料：状态②点头像/昵称区 → 进入③完善资料 → 保存成功返回②并刷新展示。
  • 退出登录：状态②点「退出登录」→ 清登录态 → 回状态①；本地错题保留。
  • 注销账号：状态②点「注销账号」→ 弹⑤二次确认 → 确认后删除云端数据 + 清除本地全部数据 → 回状态①。

三、状态差异说明

  • 状态①与②为同一页面的两种登录态；差异仅在头部卡片与下方操作列表，页面骨架（NavBar + tabBar）不变。
  • ④ 的弹层须提供「暂不登录」，取消后回到原页面，符合小程序「不得强制登录」的审核要求。
  • ⑤ 为纯复用组件，无需新设计；确认按钮用危险色区分。

四、同类产品参考点（定向调研）

  1. 个人信息头块置顶：主流个人中心以「圆形头像 + 昵称」作为头块，点击可改头像/昵称。（参考：个人中心信息架构通用范式）
  2. 未登录 = 引导而非强制：微信登录规范要求有 tabBar 的小程序至少可见首页与「我的」，支持游客模式；授权必须由用户行为触发。（参考：微信开放社区登录授权规范讨论）
  3. 受限操作触发式登录：登录入口置于 tabBar 页与受限操作点；弹窗须含「取消/暂不登录」，取消后可退回。（参考：小程序登录原型设计实践）
  4. 危险操作弱化 + 二次确认：退出/注销以列表行呈现，注销用红色并在二次确认中说明后果。
  5. 头像昵称需用户主动提供：chooseAvatar + nickname 输入控件，不能静默获取。（参考：微信官方《获取头像昵称》）
