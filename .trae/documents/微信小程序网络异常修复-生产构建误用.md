## 1. 摘要（结论先行）

**根因（已实测确认，唯一主因）**：`client/dist/` 里躺着的是**生产模式**构建产物，`API_BASE` 被编译成**占位域名** `https://api.example.com`，该域名不存在 → DNS 解析失败 → `Taro.request` 抛错 → 命中 [request.ts L84-87](file:///d:/Users/weij/ai-error-learn/client/src/services/request.ts#L84-L87) 的兜底文案「网络异常，请检查网络后重试」。

请求地址根本没到后端，**与后端、DB、域名校验都无关**。

## 2. 修复步骤（按顺序执行）

### 步骤 0：生成会话任务跟踪文件（项目规则）

在仓库根目录生成/刷新 `todo.md`，列清本次任务总数与完成状态。

### 步骤 1：以**开发模式**重新构建（核心修复）

```powershell
cd d:\Users\weij\ai-error-learn\client
npm run dev:weapp        # = taro build --type weapp --watch → NODE_ENV=development → .env.development
```

- 该命令以 watch 模式常驻，会覆盖 `dist/`；**不要**用 `npm run build:weapp`（那是生产构建，会再次写入 `api.example.com`）。
- 已有其它 `npm run server` 进程在跑，本次不影响，无需停。

**验收点（必须全部满足）**
- `dist/common.js` 中 `192.168.60.37` 出现 **≥1 次**
- `dist/common.js` 中 `api.example.com` 出现 **0 次**
- `npm run dev:weapp` 无 TS/构建报错

### 步骤 2：微信开发者工具收尾（需你在 IDE 操作）

1. 菜单 **工具 → 清除缓存 → 全部清除**，然后 **重新编译**（让 IDE 重新读取新的 `dist/`）。
2. **详情 → 本地设置**：确认「**不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书**」处于**勾选**状态（私有配置已是 `urlCheck:false`，一般无需再动，仅复核）。
3. Console 复现一次登录：报错 URL 应变为 `http://192.168.60.37:8000/api/v1/auth/login`。
   - 返回 `{"code":0,...}` → 登录成功，修复完成；
   - 返回 `{"code":2004,...}` → 网络已通，问题转为 `WECHAT_APP_SECRET` 与 AppID `wxf7fbaf8d9a6f7296` 是否匹配（另案，非本次范围）；
   - 仍报 `ERR_NAME_NOT_RESOLVED` → 说明 IDE 仍加载旧产物，回到步骤 2.1 再清一次缓存/重新编译。

### 步骤 3：清理冗余 uvicorn 实例（可选，建议）

当前 2 组实例（PID 30092/5616 与 14188/24640）争用 8000，后启动的一组绑定失败、只是徒增日志噪音（`--reload` 模式下尤其容易导致"改了不生效"的错觉）：

```powershell
# 列出
Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
  Where-Object { $_.CommandLine -like '*uvicorn app.main:app*' } |
  Select-Object ProcessId, CreationDate
# 全部 Stop-Process -Id <PID> -Force，再单实例重启：
cd d:\Users\weij\ai-error-learn\client ; npm run server
```

> 不做也不影响本次修复（8000 有且在监听），仅属环境整洁。

### 步骤 4：防复发（可选，建议做）

本 bug 的隐蔽点在于：**用错一条 npm 脚本，就会静默产出指向占位域名的包**，且只在点「登录」时才暴露。建议在 [constants/index.ts](file:///d:/Users/weij/ai-error-learn/client/src/constants/index.ts#L30-L31) 的 `API_BASE` 定义下方加 4 行**开发期告警**（纯 `console`，不侵入界面，不影响线上逻辑）：

```ts
// 误用生产构建（npm run build:weapp）做本地联调时，会指向占位域名，此处显式告警
if (API_BASE.includes("api.example.com")) {
  console.error(
    "[config] API_BASE 仍为占位域名 api.example.com：开发联调请用 npm run dev:weapp（开发构建）；生产部署请先在 .env.production 配置真实域名",
  );
}
```

- 不改变任何业务行为与 UI；若你不想动代码，可**跳过本步**（其余步骤已足以修复问题）。
