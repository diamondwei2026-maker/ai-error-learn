## 1. 摘要（结论先行）

前端「网络异常」文案有两个来源，本次报错命中**第 2 种**：

| 来源 | 位置 | 触发条件 |
| --- | --- | --- |
| 「网络异常，请检查网络后重试」 | [request.ts L84-87](file:///d:/Users/weij/ai-error-learn/client/src/services/request.ts#L84-L87) | `Taro.request` **抛错**（请求根本没发出去 / 被平台拦截 / 超时） |
| 「网络异常，请稍后重试」 | [request.ts L58-65](file:///d:/Users/weij/ai-error-learn/client/src/services/request.ts#L58-L65) | 收到响应但**信封里没有 code**（如 404/500 的 `{"detail": ...}`） |

**根因判定（按可能性排序）**

| 级别 | 根因 | 状态 |
| --- | --- | --- |
| **R1 主因（高）** | 请求在**微信侧就被拒/超时**：`client/project.config.json` 的 `setting.urlCheck: true`（= 开发者工具「校验合法域名」开启），而 dev 后端是 `http://192.168.60.37:8000`（IP + HTTP，非白名单域名）→ 平台直接拒绝 → `Taro.request` 抛错 → 「网络异常」 | 待用户侧一步确认（见 §4 步骤 4） |
| **R2 确定存在（必须修）** | `server/.env` 的 `DATABASE_URL` = `rm-bp10q72z75es2z24f.mysql.rds.aliyuncs.com`：① **不是合法连接串**（缺 `scheme://账号:密码@主机:3306/库`），后端一旦加载**启动即失败**；② 该主机解析为 `172.26.250.233`（内网/VPC），本机 TCP 3306 **6 秒超时不可达** → 登录链路（必经 `find_or_create_user` 写库）会**挂到前端 15s 超时** → 同样报「网络异常」 | 已实测确认 |
| **R3 确定存在（必须修）** | 8000 端口上跑的是 **2026/10/14 14:00 启动的旧后端实例**（`/api/v1/security/text-check`、`/api/v1/wechat/callback` 均 404，即最近一次提交的新代码没生效）；另有 10/15 18:47 启动的第二个 uvicorn 实例 → 端口争用 + 配置漂移 | 已实测确认 |

已排除：**系统代理**（`127.0.0.1:7897`，其 `ProxyOverride` 含 `192.168.*`，实测直连/走代理均 HTTP 200）；**VPN 虚拟网卡**（`LetsTAP` 未 Up）。

### 2.3 关键代码事实

1. 登录链路必写库：`POST /api/v1/auth/login` → `wechat_service.code2session()` → `auth_service.find_or_create_user(db, ...)`（[auth.py L32-43](file:///d:/Users/weij/ai-error-learn/server/app/api/auth.py#L32-L43)）→ **DB 不可达会直接挂住**。
2. 前端请求超时 15s（`REQUEST_TIMEOUT`），后端 `code2session` 超时 10s。
3. 错题本为**本地优先**：首页/题库/刷题不依赖网络，因此「网络异常」只会在**登录 / 识别 / 云同步**这类联网动作上暴露 → 与用户「只在微信登录时看到」的反馈吻合。
4. `configure_database()` 对非 `sqlite` 串直接 `create_engine(url)`（[session.py L22-29](file:///d:/Users/weij/ai-error-learn/server/app/db/session.py#L22-L29)），非法串会抛 `Could not parse SQLAlchemy URL` → **后端起不来**（`server/.env` 不入库，见 `.gitignore` L25）。

## 3. 修复方案（按顺序执行）

### 步骤 0：生成会话任务跟踪文件
在仓库根目录生成/刷新 `todo.md`（用户规则），列清本次任务数与完成状态。

### 步骤 1：修正 `server/.env`（阻塞后端启动，必做）

将 `DATABASE_URL` 改回本地开发口径：

```
DATABASE_URL=sqlite:///./app.db
```

- 该文件不入库（`.gitignore` 已忽略 `.env`），属**本机环境修复**，不影响仓库与线上。
- 原有 SQLite 数据（`server/app.db`）继续沿用，不丢数据。
- 若确需连 RDS，必须写完整串：`mysql+pymysql://<账号>:<URL编码后的密码>@<主机>:3306/error_learn?charset=utf8mb4`，且该主机必须对本机可达（当前 `172.26.250.233` 为内网地址，本机不可达）。

### 步骤 2（可选，建议）：开发期关闭内容安全
追加一行，消除开发环境对微信接口 / IP 白名单的依赖与额外延迟（保存昵称、错题时会同步调用微信）：

```
CONTENT_SECURITY_ENABLED=false
```
说明：不改代码，仅本机 `.env`；生产环境由 `deploy/env.production.example` 控制，不受影响。

### 步骤 3：清理遗留后端实例，只保留一个

当前存在两组 uvicorn 进程（10/14、10/15）争用同一 8000 端口，必须先全部停掉：

```powershell
# 1) 列出所有 uvicorn 进程
Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
  Where-Object { $_.CommandLine -like '*uvicorn app.main:app*' } |
  Select-Object ProcessId, CreationDate, CommandLine
# 2) 逐个 Stop-Process -Id <PID> -Force（父进程与子进程都要停）
# 3) 确认端口已释放（无输出即释放）
netstat -ano | Select-String ":8000"
```

### 步骤 4：用 venv 干净启动单实例

```powershell
cd d:\Users\weij\ai-error-learn\server
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --env-file .env
```

**验收点（必须全部满足）**
- 启动日志**无** `Could not parse SQLAlchemy URL`、无 `address already in use`
- `curl http://127.0.0.1:8000/api/v1/health` → `{"status":"ok"}`
- `curl http://127.0.0.1:8000/openapi.json` 中出现 `/api/v1/security/text-check` 与 `/api/v1/wechat/callback`

### 步骤 5：微信开发者工具侧确认（R1 的直接确认点，需用户操作）

1. 开发者工具 → **详情 → 本地设置** → 勾选「**不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书**」（开发环境用 IP + HTTP 访问后端时必须勾选）。
2. **清缓存并重新编译**：菜单「工具 → 清除缓存 → 全部清除」，然后重新编译；确认 `client/src` 最近改动已被 `npm run dev:weapp`（当前 watch 构建仍在跑）编译进 `dist/`。
3. 打开 **Console / Network** 面板，复现一次「微信一键登录」，确认失败请求的具体形态：
   - `request:fail`（域名/证书/网络层）→ 属 R1，勾选后应恢复；
   - 有响应但 15s 才失败 → 属 R2（DB 挂起），按步骤 1-4 修复后应恢复；
   - 响应 `{"code":2004,...}` → 属**微信密钥不匹配**，需在 MP 后台核对 `WECHAT_APP_SECRET` 是否属于 `wxf7fbaf8d9a6f7296`。
4. 若上述均正常仍报错，再检查是否开启了会劫持 Chromium 流量的代理/VPN（本次已排除，如开启请加 `192.168.*` 直连规则）。

> 备注：若第 1 步勾选后开发者工具回写 `urlCheck: false` 到 `client/project.config.json`，是否提交由用户决定；建议**不提交**（该文件此前 `urlCheck: true` 已长期共存，属本机 IDE 设置）。
