## 2. 关键事实（决定了方案形态）

1. **隐私功能已默认全量启用**：2023-10-17 起，不论 `app.json` 是否配置 `__usePrivacyCheck__`，隐私相关功能都会启用（微信官方指南「二、接入流程」）。→ **无需**在 [app.config.ts](file:///d:/Users/weij/ai-error-learn/client/src/app.config.ts) 增加该开关。
2. **不响应也不会崩，但会失控**：若开发者未注册 `onNeedPrivacyAuthorization`，微信会**自动弹官方弹窗**；一旦注册就必须自己 `resolve`，否则原接口调用会一直 pending。→ 我们采用**自定义弹层**（可控、可放协议入口），并保证同意/拒绝两条分支都 `resolve`。
3. **不声明=直接禁用**：必须在 MP 后台《用户隐私保护指引》里声明对应类型，否则调用报 `errno 112 / appid privacy api banned`，且**提审时勾选"未采集隐私"会回收接口权限**。→ 后台声明属你方动作，代码侧只保证流程正确。
4. **已核实的接口能力**：Taro 4.x 官方支持 `Taro.getPrivacySetting` / `Taro.onNeedPrivacyAuthorization` / `Taro.requirePrivacyAuthorize` / `Taro.openPrivacyContract`（已确认文档存在）。
5. **`<input type="nickname">` 是特例**：未同意隐私政策时**不会**触发 `onNeedPrivacyAuthorization`，而是**静默降级为普通文本输入**（微信官方指南「三-3」）。→ 这是本方案必须"主动先弹"的直接原因。
6. **当前涉及隐私能力的调用点**（全仓已核实）：
   - `Taro.chooseMedia` — [captureService.ts](file:///d:/Users/weij/ai-error-learn/client/src/services/captureService.ts#L12)
   - `<Button openType="chooseAvatar">` — [profile/edit/index.tsx](file:///d:/Users/weij/ai-error-learn/client/src/pages/profile/edit/index.tsx#L72)
   - `<Input type="nickname">` — [profile/edit/index.tsx](file:///d:/Users/weij/ai-error-learn/client/src/pages/profile/edit/index.tsx#L85-L93)
7. **App 组件不能承载全局弹层**：小程序端 `app.tsx` 的 render 不渲染页面节点，因此隐私弹层**必须逐页挂载**（微信官方 demo4 也是"多页面处理"）。

## 3. M1 · 隐私授权接入（阻塞项 ★）

### 3.1 策略：主动弹 + 被动兜底

| 时机 | 做法 | 解决的问题 |
| --- | --- | --- |
| 小程序启动 | `Taro.getPrivacySetting()` → `needAuthorization === true` 则直接弹隐私弹层 | 让用户在**用之前**就同意，避免 `input type="nickname"` 静默降级、避免首次拍照中途被打断 |
| 任意隐私接口被调用 | 兜底注册 `Taro.onNeedPrivacyAuthorization` → 弹同一弹层 → 同意/拒绝后 `resolve` | 覆盖"启动时已同意、后续后台更新指引新增声明项"的场景 |

### 3.2 新增文件

| 文件 | 职责 |
| --- | --- |
| `client/src/store/privacyStore.ts` | zustand：`visible`、`contractName`、`resolveRef`；`open/resolveAgree/resolveDisagree/reset` |
| `client/src/services/privacyService.ts` | 仅 weapp 生效（`isWeapp` 判定，H5/alipay 直接 noop）；`init()` 注册监听、`checkOnLaunch()` 主动查询、`openContract()`、`requireAuthorize()` |
| `client/src/components/PrivacySheet/index.tsx` + `index.module.scss` | 底部弹层（复用 `LoginSheet` 的面板规范：遮罩 + 毛玻璃 + 圆角），标题「用户隐私保护提示」，正文说明 + 「查看完整版政策」（跳 M2 页面）+「查看平台隐私协议」（`Taro.openPrivacyContract`） |

**关键实现约束（必须遵守）**：
- 同意按钮必须是**原生按钮**：`<Button id="agree-privacy-btn" openType="agreePrivacyAuthorization" onAgreePrivacyAuthorization={...}>`；`resolve` 时传 `{ buttonId: 'agree-privacy-btn', event: 'agree' }`，微信会校验该按钮是否真被点过。
- 拒绝分支必须 `resolve({ event: 'disagree' })`，否则原接口永久 pending。
- 弹层曝光时调 `resolve({ event: 'exposureAuthorization' })`（官方建议，非必须）。
- 用户拒绝后再次调用隐私接口，微信 10 秒内不再弹窗并直接报错（错误码 103/104）→ 需在调用侧给出**友好提示 + 重试引导**。

### 3.4 文案（草案，最终须与 MP 后台指引一致）

> 标题：用户隐私保护提示
> 正文：感谢你使用「错题本」。在使用前，请阅读并同意**《用户协议》**和**《隐私政策》**。
> 为了提供错题识别与多设备同步服务，我们会收集你主动选择的**照片/相册图片**、你的**微信头像与昵称**，以及**微信登录标识**用于账号识别。图片仅用于识别题目文字，不会用于其他用途。

### 3.5 验收

1. 开发者工具「清除授权数据」→ 重新进入小程序 → **首启即弹隐私弹层**。
2. 同意后：拍照录入、更换头像、昵称（可唤起微信昵称快捷填充）全部正常。
3. 拒绝后：拍照入口给出明确提示，**不崩溃、不卡死**；再次操作可重新授权。
4. `查看平台隐私协议` 能正常打开。
5. H5 预览（`build:h5`）不报错、不弹层。

### 3.6 回滚

移除 6 个页面的 `<PrivacySheet />` 与 `app.tsx` 的 `privacyService` 调用即恢复原状（微信自动回退到官方弹窗），不影响其他功能。

## 11. 假设与决策

1. **隐私弹层形态**：采用**底部弹层**（对齐 `LoginSheet`/`ActionSheet` 既有规范），而非居中卡片；理由是与现有"同意类"交互一致，且不新增视觉体系。
2. **协议页面**：隐私政策与用户协议**合并为一个页面**、query 区分；理由是两个页面结构同构，避免重复代码。
3. **不做的事**（明确边界）：清理 `services/cloud.ts` 死代码、接入 `imgSecCheck` 图片安全、AI 生成内容标识、后端结构化日志 —— 均**不在本次范围**。
4. **文案责任**：协议文本由我按上述要点起草，**最终上线前需你确认**（尤其第三方 AI 处理披露与联系方式）。
5. **未定项**：M3 是否执行，取决于你在 MP 后台确认 `security.msgSecCheck` 权限；若受限则跳过或降级为本地敏感词。
