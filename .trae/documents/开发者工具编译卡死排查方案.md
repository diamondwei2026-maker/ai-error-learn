# 微信开发者工具「编译」卡死排查与恢复方案

> 日期：2026-11-12 ｜ 类型：环境/工具问题排查（不改业务代码）

---

## 一、现象

在微信开发者工具中点击「编译」后，**一直卡住不结束，无任何报错**；CLI 侧 `npm run build:weapp` 可正常完成。

## 二、排查结论：代码中没有死循环

### 2.1 源码循环复核

全量检索 `client/src` 下的 `while` / `do…while` / 无步进 `for` / 递归自调用：**均无**。仅有两处定时器，且都会在流程结束或页面卸载时清理：

- [edit/index.tsx 第 72 行](file:///d:/Users/weij/ai-error-learn/client/src/pages/edit/index.tsx#L72-L80)：识别进度 `setInterval`，`clearInterval` 在 `await` 后立即执行；
- [quiz/index.tsx 第 86 行](file:///d:/Users/weij/ai-error-learn/client/src/pages/quiz/index.tsx#L86)：刷题计时器。

本次新增的 [textHash.ts](file:///d:/Users/weij/ai-error-learn/client/src/utils/textHash.ts) 中所有循环都是**固定边界**：

| 循环 | 边界 |
| --- | --- |
| `utf8Encode` 的 `for (i < input.length; i += 1)` | 输入字符串长度，且代理对分支内 `i += 1` 后仍由外层继续递增，不会原地打转 |
| `sha256Hex` 外层 `offset += 64` | `paddedLength`（由输入长度计算，最大 ~64 字节对齐） |
| `sha256Hex` 内层 16 / 48 / 64 轮 | 常量 |

结论：无界循环不存在。

### 2.2 时间线与进程证据

| 时间 | 事实 |
| --- | --- |
| 13:33:35 / 13:33:39 | 本次修改写入 `textHash.ts`、`questionService.ts` |
| 13:33:36 | 微信开发者工具编译子进程 `corecompile`（PID 16240）启动，**至今未退出** |
| 13:41:16 | Taro `npm run build:weapp` 成功，`dist` 全量重新生成（53 个文件、最大 132KB，无异常大文件 / 无 sourcemap / 无 node_modules） |

即：**卡住的是开发者工具的编译 worker，不是我们的源码**。CLI 构建同一份源码可在 42s 内成功，产物结构正常。

### 2.3 根因判断（工具侧）

结合上述证据，最可能的原因按概率排序：

1. **编译过程中 `dist` 被 Taro 整体重建**（13:40 那次构建删除了 63 个旧文件再生成新文件），开发者工具的编译/文件监听持有旧句柄，陷入等待 → worker 挂死；
2. **「编译时热重载」与 Taro watch 双重触发**：`project.private.config.json` 中 `compileHotReLoad: true`（覆盖了 `project.config.json` 的 `false`），源码/产物变动会反复触发编译，容易叠加成卡死；
3. 开发者工具编译缓存损坏（长时间未清理），属于该工具的已知问题，表现为无报错卡死。

## 三、处置步骤（按顺序执行，每步后可重新点「编译」验证）

1. **结束卡死的编译进程**：任务管理器结束 PID 16240（`微信web开发者工具\node.exe … corecompile`），或直接完全退出微信开发者工具（含托盘/后台进程）后重开。
2. **清除工具缓存**：开发者工具 → 菜单「工具」→「清除缓存」→「全部清除」。
3. **保证产物完整后再编译**：先在 `client` 目录执行 `npm run build:weapp`，等其 **exit 0** 结束后，再在开发者工具里点「编译」；**不要在 Taro 构建过程中点编译**。
4. **关闭编译时热重载**：`client/project.private.config.json` 的 `setting.compileHotReLoad` 由 `true` 改为 `false`，避免与 Taro 构建互相触发。
5. 若仍卡死（兜底）：
   - 在「详情 → 本地设置」临时关闭 `增强编译`（`enhance`）与「API 自动补全」（`useApiHook: true`），再编译；
   - 关闭当前项目、删除工具里该项目的缓存后重新「导入项目」，目录选 `client`（`miniprogramRoot` 已是 `dist/`）。

> 全程**不改动业务代码**。若第 1–3 步后恢复正常，可判定为工具侧瞬时卡死，无需进一步处理。

## 四、若第 5 步仍无法编译的进一步定位

按以下顺序缩小范围（属于兜底路径，非默认执行）：

1. 用 `npm run dev:weapp`（watch）验证 Taro 编译是否稳定完成，排除构建耗时被误判为卡死；
2. 将 `client/project.private.config.json` 临时移出（工具会回落到 `project.config.json`），验证是否为私有配置覆盖导致；
3. 用工具新建空白项目指向 `client/dist`，验证是否为原项目缓存问题。

## 五、验证标准

- 开发者工具点「编译」在 1 分钟内结束，底部出现「编译成功」，模拟器正常渲染首页；
- 真机预览/真机调试可正常打开；
- 首页 → 拍照识别 → 保存入库 → 题库列表出现新题（回归上一轮修复）。

## 六、风险与回滚

| 项 | 说明 |
| --- | --- |
| 结束进程 | 仅影响开发者工具自身，重新打开即恢复 |
| 清缓存 | 会清除工具的编译缓存与模拟器数据，不影响 `dist` 与源码；小程序本地 Storage 若被清，重新登录即可 |
| 关闭 `compileHotReLoad` | 只是不再自动编译，需手动点「编译」，不影响功能 |
| 回滚 | 若某步无效，将 `compileHotReLoad` 改回 `true` 即可恢复原状 |
