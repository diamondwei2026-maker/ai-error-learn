# 方案 · 首次登录引导获取微信昵称/头像

- 类型：**普通轻量增量**（/plan，不改主 spec）
- 关联既有增量：`incr-20261014-用户系统`
- 建议增量编号：`incr-20261014-首次登录资料引导`
- 目标：用户**第一次登录**后，主动引导其通过微信「头像昵称填写能力」完善昵称与头像

---

## 1. 行业调研结论（生成原型/编码前必读）

先联网调研了同赛道与微信官方规则，核心参考点 5 条：

1. **技术路径唯一**：`wx.getUserProfile` / `wx.getUserInfo` 已于 2022-10-25 起被收回，真机默认返回**灰色头像 + "微信用户"**，且不再弹授权框。现行官方唯一路径是「**头像昵称填写能力**」：`<button open-type="chooseAvatar">` 取头像临时路径 + `<input type="nickname">` 由用户在键盘上方确认微信昵称。→ **无法静默/一键获取，必须用户主动提供。**
2. **审核红线**：微信审核明确驳回「一进入小程序、未体验功能即要求授权头像/昵称/手机号」。合规姿势是——先让用户浏览/体验功能，用户主动触达后再引导授权。
3. **登录与资料完善分离**：主流做法是先完成登录（`wx.login` 静默换 openid），登录成功后再引导「完善资料」；不在登录按钮上捆绑资料授权。
4. **完善资料作为独立二级页**是最通行范式：个人中心头块置顶、点击进入修改；首次登录时把用户引到该页填写。
5. **必须可跳过**：资料完善须提供「跳过/暂不设置」，不得强制；仅**首次**引导，之后从「我的」可随时再改。

> **决策（采纳主流方案）**：登录成功后，若用户**昵称为空（首次）**，自动进入现有「完善资料」页（新增「首次引导态」，含「暂不设置」），复用现有页面与视觉体系；**可跳过**（已与需求方确认）。

## 3. 变更方案

### 3.1 触发逻辑（核心）

- `userStore.login()` 返回值由 `Promise<void>` 改为 **`Promise<UserProfile>`**（返回 `session.user`），供调用方判断（2 个调用点均为 `await login()`，向后兼容）。
- 新增导出判定辅助 `shouldGuideProfileSetup()`（放在 [userStore.ts](file:///d:/Users/weij/ai-error-learn/client/src/store/userStore.ts)）：
  - 条件：`已登录 && user.nickname 为空 && 本地未标记过「已引导」`。
- 新增本地标志键 `u:nickPrompted`（仅首次引导一次；用户**保存或跳过**后置位）：
  - [constants/index.ts](file:///d:/Users/weij/ai-error-learn/client/src/constants/index.ts)：`STORAGE_KEYS.nickPrompted = 'u:nickPrompted'`。
  - [authRepo.ts](file:///d:/Users/weij/ai-error-learn/client/src/services/repo/authRepo.ts)：新增 `isNicknamePrompted()` / `markNicknamePrompted()`；`clearAll()`（注销）一并移除该键。
- 登录成功后（2 个调用点各自）：
  - `await login()` → 关闭原有登录弹层 → 若 `shouldGuideProfileSetup()` 为真 → `Taro.navigateTo({ url: '/pages/profile/edit/index?mode=onboarding' })`。
  - **首页场景不自动续跑「拍照采集」**：用户返回后主动再点入口（符合微信「用户主动」规范，且不打断）。
- 仅发生在**登录动作之后**，**不在 `app.tsx` 启动时**触发 → 不违反「进入即授权」审核红线。

### 3.2 「完善资料」页新增「首次引导态」

- 读取路由参数：`mode`（`useRouter()`）。
- `mode === 'onboarding'` 时：
  - 说明区增加一句引导文案（如「设置头像和昵称，让错题本更像你」）。
  - 底部操作区在「保存」下方增加次要按钮「**暂不设置**」（复用 `AppButton variant="text"`）。
  - 点「暂不设置」：`markNicknamePrompted()` → `navigateBack`（返回来路页）。
  - 点「保存」成功：`markNicknamePrompted()` → 走现有成功逻辑（`showToast` + 返回）。
  - 页面标题仍为「完善资料」（`index.config.ts` 不变）。
- 非 `onboarding`（从「我的」进入）：**行为完全不变**（不出现「暂不设置」）。
- 复用现有头像 `chooseAvatar` 与 `input type="nickname"`，无需新增组件/依赖。

### 3.4 明确不做（Out of Scope）

- 不使用已废弃的 `wx.getUserProfile` / `wx.getUserInfo`（真机返回匿名数据且违规）。
- 不强制授权（已确认可跳过）。
- 不在启动时/未触达功能前弹授权。
- 不改后端接口、数据模型、同步逻辑。
- 不做「我的」页之外的入口改造（题库/刷题等不受影响）。

| # | 决策 | 说明 |

| D1 | 采用「登录后自动进入完善资料页」而非新增独立弹层 | 主流范式、复用度最高、审核最友好 |
