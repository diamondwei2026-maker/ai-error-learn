## 1. 摘要（结论先行）

**根因（已实测确认）**：`client/dist/` 当前是**开发模式**构建产物 —— [common.js L670](file:///d:/Users/weij/ai-error-learn/client/dist/common.js#L670) 抽出的 `API_BASE = "http://192.168.60.37:8000"`（构建时间 `2026/10/16 16:16:19`）。体验版就是从这个 `dist/` 上传的，于是：

- 真机访问的是**局域网 IP + HTTP**：不在微信「服务器域名」白名单、非 HTTPS、且手机不在该局域网时根本不可达；
- 开发工具里之所以"本地没事"，是因为 [project.private.config.json L6](file:///d:/Users/weij/ai-error-learn/client/project.private.config.json#L6) 的 `urlCheck: false` **只在开发者工具生效**，体验版/正式版一律强制校验合法域名；
- `Taro.request` 因此失败，命中 [request.ts L84-87](file:///d:/Users/weij/ai-error-learn/client/src/services/request.ts#L84-L87) 的兜底文案「网络异常，请检查网络后重试」。

**并存的第二个必爆点**：[.env.production L3](file:///d:/Users/weij/ai-error-learn/client/.env.production#L3) 仍是占位域名 `https://api.example.com`。也就是说，**即使改回生产构建，也依然连不上**（该域名不存在 → DNS 失败 → 同样报「网络异常」）。两个问题必须一起修。

### 8.2 ✅ 结论更正：当日"本机不可达"实为**公司内网假象**（源站一直正常）

> 📌 **勘误说明**：本节初稿曾把"本机 `curl` 失败"判定为"服务器未配 443/证书"，并列为**阻塞项**。经手机 4G 复测与服务器侧排查，**该判定被推翻**——源站一直可正常提供服务，本机失败是**公司内网中间层拦截**造成的**假象**。以下为更正后的完整结论。

**最终事实**：

| 探测 | 结果 | 判读 |
| --- | --- | --- |
| **手机 4G** 打开 `https://errorlearn.diamondwtech.com/api/v1/health` | **`{"status":"ok"}`** | ✅ **公网链路完全正常**（DNS / 443 / 证书 / 反代 / 后端全部 OK） |
| 本机 `curl https://errorlearn.diamondwtech.com/api/v1/health` | `curl: (35) Recv failure: Connection was reset` | ❌ 公司内网对非白名单域名 443 直接 reset |
| 本机 `curl http://errorlearn.diamondwtech.com/` | **HTTP 403**，响应头 **`Server: Beaver`** | ❌ `Beaver` **不是 Nginx 的标识**（Nginx 只会写 `Server: nginx`）→ 403 由**中间层**返回，非源站 |
| 服务器本机 `curl -H "Host: errorlearn.diamondwtech.com" http://127.0.0.1/` | **301** | ✅ 源站配置本身正确 |
| 源站 `access.log` | 全程**只有 301/200/400，无 403**；且外部 IP（Censys 等）请求 `/` 拿到 301 | ✅ 坐实"那个 403 没经过我们的 Nginx" |

**根因（更正后）**：本机所在**公司内网**存在透明代理 / 上网行为管理设备，对**非白名单域名**直接返回 `403`（`Server: Beaver`）或对 443 直接 **reset**，从而制造"域名不可达"的假象。**与服务器配置无关。**

**服务器侧的实际处置（确有其事，已修复）**：排查中确认该域名当时**只有 80 的 server 块、缺 `listen 443` + 证书**（`nginx -t` 照样通过），已按部署教程 §9.4 补全 80 + 443 两块并 `reload`。补全后手机 4G 验证通过。

**教训（已沉淀进部署教程 §13.4）**：
1. **不要用"自己电脑（尤其公司内网）"的结果给域名可达性定性**，必须用**手机移动数据**或**全国多节点拨测**；
2. 看响应头 `Server:` 是分辨"源站 vs 中间层"的快捷判据：`nginx` = 源站，`Beaver` = 中间层拦截页；
3. 进一步佐证：源站 `access.log` 里**有没有**该请求——没有就说明请求根本没到源站。

**剩余待办（用户侧）**：mp 后台配 `request`/`uploadFile`/`downloadFile` 合法域名 → 生产构建上传 → **选为体验版 → 手机 4G 真机复测登录**。
