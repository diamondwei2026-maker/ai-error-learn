## 1. 摘要

当前仓库**内容安全能力为 0**：全仓无 `msgSecCheck` / `mediaCheckAsync`，也**没有微信 `access_token` 获取与缓存逻辑**（[wechat_service.py](file:///d:/Users/weij/ai-error-learn/server/app/services/wechat_service.py) 仅有 `code2session`）。

本次落地微信内容安全接入，覆盖**全部 UGC 写入点**：

| 内容 | 校验接口 | 时机 | 命中处置 |
| --- | --- | --- | --- |
| 昵称 | `msgSecCheck` v2（scene=1 资料） | `PATCH /user/me` 同步校验 | 拦截，返回 2007 |
| 错题题干 / 答案 | `msgSecCheck` v2（scene=3 论坛） | ① 前端保存前预检 ② 服务端 `sync/push` 兜底 | 拦截，返回 3002 / push 列入 `rejected` |
| 头像图片 | `mediaCheckAsync` v2（scene=1 资料） | 上传后异步送检，结果经消息推送回调 | 回调命中违规 → 删除头像文件并清空 `avatar_url` |

**统一降级策略（已确认）**：未配置 `WECHAT_APP_SECRET` / 接口报错 / 无权限 / IP 未白名单 → **放行 + 记日志**，绝不阻塞用户写入。

**不做**：题干原图（不落盘、仅透传给识别模型）送检；AI 生成内容标识；本地敏感词表。

### 2.2 微信接口契约（官方核实）

**A. 获取调用凭据（推荐 stable_token）**
```
POST https://api.weixin.qq.com/cgi-bin/stable_token
body: {"grant_type":"client_credential","appid":..,"secret":..,"force_refresh":false}
resp: {"access_token":"..","expires_in":7200}
```
- 普通模式下有效期内重复调用**不会**失效旧 token → 适合多进程共存。
- 需在 MP 后台配置 **IP 白名单**（否则 `40164`）。

**B. 文本检查 `msgSecCheck` v2**
```
POST https://api.weixin.qq.com/wxa/msg_sec_check?access_token=..
body: {"content":..,"version":2,"scene":1|2|3|4,"openid":..}
resp: {"errcode":0,"result":{"suggest":"risky|pass|review","label":..},"detail":[..],"trace_id":..}
```
- `content` ≤ 2500 字（UTF-8）；`openid` 需用户近 2 小时访问过小程序（否则 `61010`）。
- 频率：4000 次/分、200 万/天；**未上架小程序 100 次/天**。
- scene 枚举：1 资料；2 评论；3 论坛；4 社交日志。

**C. 多媒体检查 `mediaCheckAsync` v2**
```
POST https://api.weixin.qq.com/wxa/media_check_async?access_token=..
body: {"media_url":..,"media_type":2,"version":2,"scene":1,"openid":..}
resp: {"errcode":0,"trace_id":".."}
```
- `imgSecCheck`（v1）**2021-09-01 已停更**，必须用本异步接口。
- `media_url` 必须可被微信服务器下载（须公网 HTTPS）。频率 2000 次/分、20 万/天；单文件 ≤10MB。
- 结果 **30 分钟内**推送到「消息推送」服务器地址，事件 `wxa_media_check`，含 `trace_id` / `result.suggest` / `errcode`（`-1008` = 媒体下载失败）。

## 4. 改造方案

### 4.1 后端 · 新增 `ContentSecurityService`

**新增** `server/app/services/content_security.py`

```python
STABLE_TOKEN_URL = "https://api.weixin.qq.com/cgi-bin/stable_token"
MSG_SEC_CHECK_URL = "https://api.weixin.qq.com/wxa/msg_sec_check"
MEDIA_CHECK_ASYNC_URL = "https://api.weixin.qq.com/wxa/media_check_async"

SCENE_PROFILE = 1   # 资料（昵称 / 头像）
SCENE_FORUM = 3     # 论坛（错题题干与答案，属 UGC 内容）

class ContentSecurityService:
    def __init__(self, appid, secret, enabled=True, timeout=10, client=None): ...
    @property
    def ready(self) -> bool: ...                       # enabled and appid and secret
    def _access_token(self) -> Optional[str]: ...      # 模块级缓存 (token, expire_at)；提前 300s 失效
    def check_text(self, text, openid, scene) -> str:  # 'pass' | 'risky' | 'review' | 'skipped'
    def check_image_async(self, media_url, openid, scene) -> Optional[str]:  # trace_id | None
```

**实现要点**
- token 缓存放**模块级 dict**（`{appid: (token, expire_at)}`），`stable_token` 普通模式不会互相失效，多 worker 各自缓存安全。
- 遇 `errcode == 40001`（token 无效）→ 清缓存**重试一次**。
- 任何异常 / `errcode != 0` / `ready == False` → `logging.warning(...)` 后返回 `'skipped'`（文本）或 `None`（图片）。**绝不上抛**。
- `client` 可注入（沿用 `WechatService` 的 httpx 直连 + 可注入风格），便于单测。

### 4.7 后端 · 消息推送回调（图片异步结果）

**新增** `server/app/api/wechat_callback.py`：`create_wechat_callback_router(settings, content_security)`，挂载于 `/api/v1` → 对外 URL `https://<域名>/api/v1/wechat/callback`

**GET（URL 有效性验证）**
1. 取 query `signature/timestamp/nonce/echostr`
2. `sha1("".join(sorted([token, timestamp, nonce])))` 比对 `signature`
3. 通过 → `PlainTextResponse(echostr)`；不通过 → `Response(status_code=403)`

**POST（事件接收）**
1. 同样验签（`token` 为空 → 记日志并 403）
2. 解析 body：**先试 `json.loads`，失败再按 XML 解析**（`xml.etree.ElementTree`）——官方 `wxa_media_check` 示例为 JSON，但 XML 格式也可能出现，两者都兼容
3. 若 `Event == "wxa_media_check"` 且 `errcode == 0` → 处理；其余事件一律忽略
4. **始终**返回 `PlainTextResponse("success")`（避免微信重试）

**处理逻辑 `_apply_media_result(db, payload)`**
- `suggest = payload["result"]["suggest"]`；兼容 `isrisky == 1` 视作 `risky`
- 按 `trace_id` 查 `MediaCheckRecord`；查不到 → 记 warning 并返回
- 更新 `verdict` + `checked_at`
- 若命中 `risky`：查 `User` → **仅当** `user.avatar_url` 仍指向该记录的 `file_name` 时，才删除 `{uploads}/avatars/{file_name}` 并置 `avatar_url = None`（防误删用户后续上传的新头像）
- `errcode == -1008`（媒体下载失败）→ `verdict = "error"` + warning 日志（放行，不删）

**`handleSave` 目标形态**
```ts
const handleSave = async () => {
  const trimmed = content.trim()
  if (!trimmed || saved) return
  setSaved(true)

  // 1) 保存前预检（仅登录态；未登录内容不会上云，跳过）
  if (isLoggedIn) {
    try {
      await securityService.checkQuestionText({ content: trimmed, answer })
    } catch (error) {
      if (error instanceof ApiRequestError && error.code === CONTENT_CODE.questionRisky) {
        setSaved(false)
        Taro.showToast({ title: error.message, icon: 'none' })
        return
      }
      // 网络/服务异常 → 降级放行（D3）
      console.warn('[edit] content pre-check skipped', error)
    }
  }

  // 2) 入库（原逻辑不变）
  try {
    await questionService.create({ content: trimmed, answer, tempImagePath: tempPath || undefined })
    refreshStore()
    setTimeout(() => Taro.switchTab({ url: '/pages/library/index' }), 1500)
  } catch (error) {
    setSaved(false)
    Taro.showToast({ title: '保存失败，请重试', icon: 'none' })
  }
```

## 9. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| IP 未加白名单 → `40164`，内容安全整体失效 | 启动告警 + 每次调用 warning 日志；上线前置清单固化 |
| 未上架小程序文本检查 **100 次/天** | 送检量已由 D7 限流（仅新增/变更项）；体验期内避免批量灌数据 |
| `openid` 近 2 小时未访问小程序 → `61010` | 三条链路均在用户操作当下触发，实际不会命中；命中即降级放行 |
| 消息推送 URL 与账号既有配置冲突 | 部署前置中列为用户确认项；冲突时可改用独立子域名或暂缓图片校验（`PUBLIC_BASE_URL` 留空即跳过） |
| 明文模式回调可被伪造 | 已做 SHA1 验签；伪造者需同时持有 Token。安全模式列为后续增强项 |
| `mediaCheckAsync` 异步 → 存在最长 30 分钟违规头像可见窗口 | 已与用户确认范围；后续可加"上传后前端暂显占位图"降低窗口 |
| 已有违规内容（方案上线前写入云端的）不会被回溯检查 | 明确为已知边界；如需回溯需一次性脚本（本次不做） |
