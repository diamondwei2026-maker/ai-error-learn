# 移除临时网络探针：修复开发者工具「example.com 不在 request 合法域名列表」报错

> 性质：轻量增量（仅删除临时调试代码 + 重建产物 + 文档记录），无业务逻辑、无 UI、无后端改动
> 触发问题：微信开发者工具控制台报 `https://example.com 不在以下 request 合法域名列表中`
> 方案日期：2026-11-10

---

## 1. 摘要（结论先行）

**该报错不是业务请求失败，而是上一轮排查 `-101` 时留下的临时网络探针造成的。**

- 报错 URL `https://example.com/` 来自 [app.tsx L46-L93](file:///d:/Users/weij/ai-error-learn/client/src/app.tsx#L46-L93) 中标记为 `TODO(debug-netprobe)` 的临时探针；
- 当前 `client/dist` 是 **2026-10-19 的生产构建**（`dist/common.js` 中 `API_BASE = "https://errorlearn.diamondwtech.com"`），该产物包含探针（`dist/app.js` 中 `example.com` 出现 1 次、`netprobe` 出现 3 次），开发者工具 `urlCheck: true` 时会直接拦截该域名；
- `-101` 根因已由 curl / 备案拦截页证据链定位为**阿里云侧备案拦截**（见根目录 [todo.md](file:///d:/Users/weij/ai-error-learn/todo.md)），探针无继续保留的必要；且 `example.com` 无法加入微信白名单，探针在任何开启域名校验的环境里都只能得到 "url not in domain list"，无法作为有效对照。

**修复方式（用户已确认）**：直接删除探针代码 → 以**生产模式**重建 `dist` → 更新任务跟踪与 change-log。
