# 错题本小程序 —— 部署教程（零基础版）

> **适用场景**：阿里云 ECS 上**已经有别的网站在跑**（原生 Nginx，80/443 被占用）+ **独立 RDS MySQL 实例** + 有一个**已备案的主域名**（要新开一个子域名）
>
> 本文假设你**从没部署过网站**。每一步都会告诉你：**在哪个窗口做、点什么、敲什么、做完应该看到什么**。
> 校对日期：2026-10-15

---

## 0. 先读这一页（3 分钟，别跳过）

### 0.1 你要操作两个"窗口"，别搞混

整个部署只涉及**两个地方**，本文每一步都会用 `【在哪个窗口】` 标出来：

| 代号 | 是什么 | 长什么样 | 用来干什么 |
| --- | --- | --- | --- |
| **【控制台】** | 阿里云官网的控制台（浏览器里的网页） | 一堆按钮、菜单、表格 | 建数据库、加白名单、看实例、连服务器 |
| **【黑框】** | ECS 的「远程连接」工作台（Workbench），是一个**黑底命令行窗口** | 黑底、可以打字、提示符形如 `root@iZxxxx:~#` | **敲命令**（装软件、启动服务） |

> 一句话：**要"点鼠标"的去【控制台】，要"敲命令"的去【黑框】。**

### 0.2 术语小卡片（看不懂就回来查）

- **命令行 / 黑框**：不是图片，是要你**打字并回车**的地方。
- **`sudo`**：以管理员身份执行。你如果本来就是 `root` 登录，加不加都行。
- **路径**：文件在服务器上的"地址"，比如 `/opt/error-learn`。
- **提示符 `#` 或 `$`**：黑框最左边那一串（如 `root@iZxxxx:~#`），它后面才是你打字的地方。
- **端口**：一台服务器上不同程序的"门牌号"，比如 Nginx 用 443、我们的后端用 8000。

### 0.3 三条"保命"操作

| 要做什么 | 怎么做 |
| --- | --- |
| **粘贴命令** | 在【黑框】里用 **`Ctrl` + `Shift` + `V`**，或**点鼠标右键**（很多浏览器不支持 `Ctrl+V`） |
| **发现敲错了 / 卡住了** | 按 **`Ctrl` + `C`** 中断，回到提示符 |
| **不确定刚才成功没** | 看本文每步的 **✅ 验证点**，照着比对 |

### 0.4 本文的阅读规则

- 每一步都标了 **【在哪个窗口】** 和 **✅ 验证点**。
- **看到 ✅ 验证点通过，再进入下一步**；不通过就看 [§13 卡住了怎么办](#13-卡住了怎么办)。
- 全文命令可以整段复制，见 [附录 A：命令速查](#附录-a命令速查可整段复制)。

> **本次部署只做"新增"，不改动你已经有的网站。**
> 不重装 Nginx、不改别的网站的配置、Nginx 只"平滑重启"（`reload`）不"整体重启"（`restart`）。撤掉本项目也不会影响你原来的网站，详见 [§14](#14-影响范围与回滚)。

```
                    ┌──────────────── 你的 ECS 云服务器 ────────────────┐

   │                 │    ├─ 原来的网站  a.com            → 不动        │

                    │              ▼                                  │
                    │     我们的后端程序（uvicorn，常驻运行）             │
                    │              │                                   │
                    │              ├─→ 独立 RDS 数据库（云数据库）        │
```

**你接下来要做的（按顺序）**：登录服务器 → 摸清现状 → 下载代码 → 建数据库 → 部署后端 → 接上 Nginx → 申请 HTTPS 证书 → 发布小程序 → 配置微信后台。

## 2. 开工前准备（勾选清单）

开始前确认你手上有这些东西：

- [ ] **ECS 云服务器**：已在运行，上面已有网站和 Nginx（本文前提）
- [ ] **独立 RDS MySQL 8.0 实例**：如果**还没创建**，见下方 2.1
- [ ] **已备案的主域名**：例如 `example.com`（备案是在阿里云"备案"里做的）
- [ ] **小程序的 AppID**：本项目为 `wx683110d829c1f0f9`
- [ ] **微信小程序后台的登录权限**（要配合法域名、隐私指引）

### 2.1 如果 RDS 实例还没创建

【控制台】阿里云 → 搜索「云数据库 RDS」→ 创建实例 → 选 **MySQL 8.0** → **地域必须与你的 ECS 相同**（例如都在"华东1 杭州"）→ 选个最小规格即可 → 设置账号密码 → 创建（等几分钟）。

> ⚠️ 只有 **ECS 与 RDS 在同一地域**，服务器才能用"内网"连数据库，又快又安全。

## 3. 第一步：登录你的云服务器（Workbench）

**这一步的目标**：在浏览器里打开一个能敲命令的【黑框】。

**【在哪个窗口】** 阿里云控制台（网页）

1. 打开阿里云官网 → 右上角登录 → 进入**控制台**。
2. 左上角搜索框输入 **`云服务器 ECS`** → 进入 ECS 控制台。
3. 左侧菜单点 **「实例与镜像」→「实例」**。
4. 在列表里找到你要用的那台服务器，点它右侧的 **「远程连接」**。
5. 弹窗里选 **「Workbench（推荐）」**（不同版本可能叫「通过 Workbench 远程连接」），点「登录」：
   - 如果提示输入密码，就填你创建 ECS 时设的密码（或点「一键登录」/「重置密码」后再登）。
6. 稍等几秒，你会看到一个**黑底窗口**。

**✅ 验证点**：黑框里出现类似下面这样一行（最后是 `#`）：

```
root@iZbp1xxxxxxxxxx:~#
```

在【黑框】里敲下面这条，回车：

```bash
whoami
```

- 看到 **`root`** → 成功，你现在是管理员，后面的命令可以不加 `sudo`。
- 看到别的内容（比如 `weij`）→ 也是正常的，**后面命令请保留开头的 `sudo`**。

## 4. 第二步：摸清服务器现状

**为什么要做**：这台服务器上已有别的网站，我们要先知道"门牌号有没有冲突"，再动手。

**【在哪个窗口】** 黑框（下面每条都逐行敲、逐行回车）

```bash
# ① 看 Nginx 版本（决定后面 HTTPS 配置怎么写）
nginx -v

# ② 看已有的网站用了哪些域名、哪些端口
sudo nginx -T | grep -E "server_name|listen"

# ③ 看已有的站点配置文件
ls -l /etc/nginx/conf.d/

# ④ 看 80 / 443 / 8000 端口分别被谁占用
sudo ss -lntp | grep -E ':(80|443|8000)\b'

# ⑤ 看 Nginx 是用哪个用户跑起来的
ps -o user= -C nginx | sort -u

# ⑥ 看有没有现成的证书工具
ls -d ~/.acme.sh 2>/dev/null; which certbot 2>/dev/null

# ⑦ 看内存和磁盘还剩多少
free -m; df -h /
```

**怎么判断**（把结果填进下面这张表，后面要用）：

| 侦察项 | 怎么判断 | 你的结论 |
| --- | --- | --- |
| ① Nginx 版本 | 输出形如 `nginx/1.24.0`。**≥1.25.1** 与 **1.24.x** 后面写法不同 | ____________ |
| ② 已有域名 | 会列出类似 `server_name a.com;` 的多行 | ____________ |
| ③ 已有配置 | `/etc/nginx/conf.d/` 下已有哪些 `.conf` 文件 | ____________ |
| ④ **8000 是否被占** | **有输出**=被占用（说明要改用 8080）；**没输出**=空闲，用 8000 | ____________ |
| ⑤ Nginx 用户 | 常见 `www-data`（Ubuntu）或 `nginx`（CentOS） | ____________ |
| ⑥ 证书工具 | 有 `~/.acme.sh` 或 certbot 路径=已有，可复用 | ____________ |

**✅ 验证点**：上面每条命令都执行完且**没有报错**；④ 那一项你已经明确知道 **8000 是否被占用**。

> 小提示：第 ④ 条如果输出里出现 `users:(("nginx",...))` 并且端口是 80/443，那是**你原来的网站**，属于正常，不用管。

## 5. 第三步：把代码下载到服务器

**这一步的目标**：把项目代码从 GitHub 下载到服务器的 `/opt/error-learn` 目录。

### 5.1 ⚠️ 先在你自己的电脑上做一件事：把最新代码推上去

**为什么**：你电脑上的代码可能比 GitHub 上"新"。如果服务器从 GitHub 拉，就会拉到**旧代码**，后面会缺文件。

**【在你自己的电脑上】**（就是你现在这个项目文件夹里）执行一次推送；如果你不确定，可以直接让助手帮你执行：

```bash
git push
```

**✅ 验证点**：本地执行 `git status` 时提示 **`nothing to commit, working tree clean`** 且 `git status` 顶部没有 `ahead of 'origin/...' by N commits`（即本地没有未推送的提交）。

### 5.2 在服务器上安装 git

**【在哪个窗口】** 黑框

```bash
git --version
```

- 如果显示 `git version x.x.x` → 已安装，**跳到 5.3**。
- 如果提示 `command not found` → 执行下面这条装一下：

```bash
sudo apt update && sudo apt install -y git
```

> 如果你的服务器是 CentOS（不是 Ubuntu），把 `apt` 换成 `yum`：`sudo yum install -y git`

### 5.3 下载代码

**【在哪个窗口】** 黑框

```bash
sudo git clone https://github.com/diamondwei2026-maker/ai-error-learn.git /opt/error-learn
```

> 这会把代码放到服务器的 `/opt/error-learn` 目录（下文把这个目录叫 **项目目录**）。

**✅ 验证点**：敲下面这条列出目录内容：

```bash
ls /opt/error-learn
```

应当看到这些名字：**`client`、`server`、`deploy`、`.trae`**（可能还有 `.docs`、`.gitignore` 等）。

### 5.4 如果下载失败（连不上 GitHub / 很慢）

国内服务器访问 GitHub 有时会超时。可以：

1. **直接重试一次**（多数情况下重试就好）。
2. 若始终失败，改用国内镜像（Gitee）或**把本地项目打包上传**（在【控制台】用文件上传，或用「宝塔面板」上传）。这一步可以让助手帮你换成备选方案。

**✅ 验证点**：`ls /opt/error-learn` 能看到 `client server deploy .trae`。

## 6. 第四步：创建数据库（点鼠标即可，不用写 SQL）

**这一步的目标**：在你的 RDS 上建一个叫 `error_learn` 的空库，并允许服务器连它。

**【在哪个窗口】** 控制台（全程点鼠标）

### 6.1 建库

1. 阿里云控制台 → 搜索 **「云数据库 RDS」** → 进入 RDS 控制台。
2. 左侧点 **「实例列表」** → 点进你那个 RDS 实例。
3. 在实例详情页找到 **「数据库管理」**（有的版本在 **「数据管理 DMS」** 里）。
4. 点 **「创建数据库」**，填写：
   - **数据库名**：`error_learn`（必须一字不差）
   - **字符集**：`utf8mb4`（下拉里选 `utf8mb4`，排序规则可选 `utf8mb4_unicode_ci`）
   - **授权账号**：选你已有的账号，或先建一个（见 6.2）
5. 点确定创建。

### 6.2 账号（如果没有现成账号）

1. 左侧 **「账号管理」** → **「创建账号」**。
2. 填账号名、密码（**记下来**，后面要填进配置文件），类型选"普通账号"或"高权限账号"。
3. 建好后回到 6.1 的「创建数据库」，把 `error_learn` 的授权账号选成它。

### 6.3 把服务器 IP 加进白名单（不做这步会连不上！）

1. 左侧 **「数据安全性」** → **「白名单」**（有的版本叫「白名单与安全组」）。
2. 点 **「添加白名单分组」** 或直接编辑默认分组。
3. 在【黑框】里查服务器内网 IP：

   ```bash
   hostname -I | awk '{print $1}'
   ```

   例如输出 `172.16.0.8`，就把它填进白名单。
4. 保存。

**✅ 验证点**：回到 RDS 的「数据库管理」，列表中能**看到 `error_learn`**；白名单里能看到你刚填的 IP。

> 说明：应用第一次启动时会**自动建表**，所以你**只需要建空库**，不需要手工建任何表，也**不用在控制台里写 SQL**。
> （如果技术人员需要 SQL，见 [附录 C](#附录-c备用给技术同学的-sql)。）

## 7. 第五步：部署后端程序

**这一步的目标**：让后端的"识别服务"在服务器上跑起来，并能被 Nginx 访问。

**【在哪个窗口】** 黑框

### 7.1 说明：关于"端口"

- 如果 §4 侦察到 **8000 空闲** → 全文用 **8000**。
- 如果 **8000 被占用** → 改用 **8080**；后面凡是出现 `8000` 的地方，都要换成 `8080`（本文会给出一键脚本自动处理）。

### 7.2 安装 Python 依赖

```bash
# 只装 Python 相关工具，不装/不升级 Nginx（服务器上已有）
sudo apt update && sudo apt install -y python3 python3-venv python3-pip curl

cd /opt/error-learn/server
python3 -m venv .venv
./.venv/bin/python -m pip install --upgrade pip
./.venv/bin/python -m pip install -r requirements.txt
```

**MySQL 8 特别注意**（必做，否则连不上数据库）：

```bash
./.venv/bin/python -m pip install "PyMySQL[rsa]"
```

**✅ 验证点**：最后一条命令以 `Successfully installed ...` 结尾，且没有红色 `ERROR`。

### 7.3 写配置文件 `.env`

这个文件存放密钥和数据库地址，**服务器上本来没有，需要你新建**。

【黑框】先复制模板：

```bash
cp /opt/error-learn/deploy/env.production.example /opt/error-learn/server/.env
```

然后编辑它。**小白推荐用 `nano`**（比 `vi` 友好）：

```bash
nano /opt/error-learn/server/.env
```

进入后是一个文本编辑器窗口，按键盘方向键移动光标，改下面这几个值：

| 要改的项 | 改成什么 |
| --- | --- |
| `VISION_API_KEY=` | 你的 AI 识别模型密钥 |
| `WECHAT_APP_SECRET=` | 微信小程序 AppSecret（**别用开发时的值**） |
| `JWT_SECRET=` | 一串随机字符，可先用 `openssl rand -hex 32` 生成后粘贴 |
| `DATABASE_URL=` | 改成：`mysql+pymysql://账号:密码@RDS内网地址:3306/error_learn?charset=utf8mb4`（把"账号/密码/RDS内网地址"换成 §6 里的真实值） |
| `UPLOADS_DIR=` | 保持 `/opt/error-learn/server/uploads` 不变 |

**`nano` 怎么保存和退出（很重要）**：

1. 改完后按 **`Ctrl` + `O`**（字母 O），再按 **回车** → 保存。
2. 按 **`Ctrl` + `X`** → 退出，回到黑框。

> **备选（完全不想用编辑器）**：可以整段粘贴重建文件，见 [附录 A-7.3](#73-写配置文件-env-的整段粘贴法)。

**✅ 验证点**：黑框回到提示符后，执行下面这条，应能看到你填的数据库连接串：

```bash
grep DATABASE_URL /opt/error-learn/server/.env
```

### 7.4 安装并启动服务（systemd）

```bash
# 若端口用 8000：直接用下面第一条；若用 8080：把 --port 8000 换成 --port 8080
sudo sed "s#<DEPLOY_DIR>#/opt/error-learn#g" \
  /opt/error-learn/deploy/systemd/error-learn-api.service \
  | sudo tee /etc/systemd/system/error-learn-api.service >/dev/null

sudo systemctl daemon-reload
sudo systemctl enable --now error-learn-api
```

**✅ 验证点**（两条都要通过）：

```bash
# ① 服务状态：应看到绿色的 active (running)
sudo systemctl status error-learn-api

# ② 本机自测：应返回 {"status":"ok"}
curl http://127.0.0.1:8000/api/v1/health
```

- ① 看到 **`active (running)`** → 服务在跑。
- ② 看到 **`{"status":"ok"}`** → 后端正常（用 8080 的话把命令里的 8000 换掉）。
- 如果失败：执行 `sudo journalctl -u error-learn-api -n 50` 看最后 50 行报错，多为 `.env` 里 `JWT_SECRET` / `DATABASE_URL` 没填好。

### 7.5 省事通道：一条命令搞定（可选）

如果你跳过了 7.2~7.4，也可以用仓库里的一键脚本（它会把上面的步骤按顺序做完）：

```bash
# 端口 8000
sudo DEPLOY_DIR=/opt/error-learn DOMAIN=api.example.com bash /opt/error-learn/deploy/deploy.sh

# 端口 8000 被占时，改用 8080（脚本会先检查端口是否空闲）
sudo DEPLOY_DIR=/opt/error-learn DOMAIN=api.example.com PORT=8080 bash /opt/error-learn/deploy/deploy.sh
```

> 脚本**不会**帮你申请 HTTPS 证书（证书见 §9），也不会改动你原来的网站。

## 8. 第六步：接上 Nginx（新增一个子域名站点）

**这一步的目标**：让 `https://api.你的域名` 转发到后端。**只新增一个文件，不动原有网站。**

**【在哪个窗口】** 黑框

### 8.1 放置站点配置

把模板里的 3 处占位（域名、证书路径）替换成你的真实值，然后写入 Nginx 配置目录：

```bash
sudo mkdir -p /etc/nginx/ssl
sudo sed \
  -e "s#api.example.com#api.example.com#g" \
  -e "s#/etc/nginx/ssl/api.example.com.pem#/etc/nginx/ssl/api.example.com.pem#g" \
  -e "s#/etc/nginx/ssl/api.example.com.key#/etc/nginx/ssl/api.example.com.key#g" \
  /opt/error-learn/deploy/nginx/error-learn.conf \
  | sudo tee /etc/nginx/conf.d/error-learn.conf >/dev/null
```

> 上面三行的 `api.example.com` 请**全部换成你的真实子域名**（比如 `api.mysite.com`）。
> 如果后端端口改成了 8080，再补一条：
> ```bash
> sudo sed -i "s#127.0.0.1:8000#127.0.0.1:8080#g" /etc/nginx/conf.d/error-learn.conf
> ```

### 8.2 校验并加载（只 reload，不 restart）

```bash
sudo nginx -t
sudo systemctl reload nginx
```

**✅ 验证点**：

- `nginx -t` 输出应包含 **`syntax is ok`** 和 **`test is successful`**。
- 若报错，多半是 **Nginx 版本与 HTTP/2 写法不符**：模板默认 `http2 on;`（需要 Nginx ≥ 1.25.1）；若你的版本是 **1.24.x**，请编辑 `/etc/nginx/conf.d/error-learn.conf`，把这行改成 `listen 443 ssl http2;` 并删掉 `http2 on;`。

> **为什么只能 `reload` 不能 `restart`？** `reload` 是"平滑重载"，不会打断你原来网站的访问；`restart` 会让 Nginx 整个重启，**你原来的网站会瞬间打不开**。共享服务器上请始终用 `reload`。

### 8.3 顺手加个 DNS 解析（在域名服务商处）

【控制台】到你的**域名解析**（阿里云叫「云解析 DNS」）里，给主域名加一条记录：

- 类型：**A**
- 主机记录：`api`（这样就是 `api.你的域名`）
- 记录值：你的 **ECS 公网 IP**

**✅ 验证点**：过几分钟后，在【黑框】执行（把域名换成你的）：

```bash
curl -v https://api.example.com/api/v1/health
```

看到 `{"status":"ok"}` 即成功（此时若证书还没好会报证书错误，属正常，先做 §9）。

## 9. 第七步：申请 HTTPS 证书

**为什么要 DNS 验证**：你的 **80 端口已经被原网站占用**，另一种常见的验证方式（HTTP-01）需要 80 端口，所以**本场景只能用 DNS 验证**。DNS 验证不占用任何端口，还能自动续期。

**【在哪个窗口】** 黑框

先准备一个「阿里云 DNS 的 AccessKey」：到【控制台】右上角头像 →「AccessKey 管理」→ 创建一个（建议只给 DNS 权限），记下 `AccessKeyId` 和 `AccessKeySecret`。

然后：

```bash
# 1) 安装 acme.sh（若 §4 侦察到已存在则跳过）
curl https://get.acme.sh | sh -s email=你的邮箱@example.com

# 2) 设置默认 CA
~/.acme.sh/acme.sh --set-default-ca --server letsencrypt

# 3) 用阿里云 DNS 自动签发（把下面两个值换成你的 AccessKey，域名换成你的）
export Ali_Key="你的AccessKeyId"
export Ali_Secret="你的AccessKeySecret"
~/.acme.sh/acme.sh --issue --dns dns_ali -d api.example.com

# 4) 把证书装到 Nginx 目录（续签后自动 reload）
sudo mkdir -p /etc/nginx/ssl
~/.acme.sh/acme.sh --install-cert -d api.example.com \
  --key-file       /etc/nginx/ssl/api.example.com.key \
  --fullchain-file /etc/nginx/ssl/api.example.com.pem \
  --reloadcmd      "sudo systemctl reload nginx"

# 5) 查看证书有效期
openssl x509 -in /etc/nginx/ssl/api.example.com.pem -noout -subject -dates
```

**✅ 验证点**：第 5 条能看到 `subject=CN = api.example.com` 和两行日期；再执行：

```bash
curl https://api.example.com/api/v1/health
```

返回 `{"status":"ok"}` → **HTTPS 通了**（这是整个部署最关键的一关）。

> acme.sh 会自动加一个定时任务去续期，不用你操心。

## 13. 卡住了怎么办

### 13.1 小白高频卡点

| 现象 | 原因 / 怎么办 |
| --- | --- |
| 敲命令提示 `Permission denied` | 权限不够，命令前面加 `sudo` |
| 命令提示 `command not found` | 这个软件没装，按教程里的安装命令装一下 |
| 粘贴没反应 | 用 `Ctrl+Shift+V` 或**鼠标右键**；别用 `Ctrl+V` |
| 卡住不动 / 想重来 | 按 `Ctrl+C` 中断 |
| GitHub 下载超时 | 重试；仍失败则改用镜像或打包上传（§5.4） |
| `nano` 里改了保存不了 | 按 `Ctrl+O` 再敲**回车**；退出按 `Ctrl+X` |
| Workbench 黑框断了 | 回到【控制台】重新点「远程连接」即可，服务器还在跑 |
| 端口被占（起服务失败） | 改用 `PORT=8080` 重来（§7.5），或看 §4④ |
| 网页打不开 `https://api.你的域名` | 依次查：DNS 解析（§8.3）→ 证书（§9）→ 安全组是否放行 443 → `sudo nginx -t` |

### 13.2 阿里云 RDS 连接错误码

| 错误码 | 现象 | 处理 |
| --- | --- | --- |
| **2003** | `Can't connect to MySQL server` | RDS 白名单没放行服务器内网 IP（回到 §6.3）；确认 ECS 与 RDS 同地域 |
| **1045 (#28000)** | 认证失败 | 账号或密码错；确认账号有 `error_learn` 库权限 |
| **1045 Access denied** | 密码校验失败 | MySQL 8 要用 `PyMySQL[rsa]`（§7.2 已装） |
| **2059** | `Authentication plugin cannot be loaded` | 同上，缺 `cryptography` 依赖，重跑 §7.2 最后一条 |
| **2006** | `MySQL server has gone away` | 连接超时或数据包过大，检查 Nginx `client_max_body_size` |

### 13.3 共享服务器专属

| 现象 | 处理 |
| --- | --- |
| `nginx -t` 失败 | 多为 HTTP/2 写法与版本不符（§8.2），或证书路径不对。`nginx -t` 只检查不生效，可放心执行 |
| 担心影响原网站 | 只要用 `reload` 就不会；若误用了 `restart`，原网站会自己恢复，无需改配置 |
| 新子域名打不开 | 检查 DNS 解析 → 安全组放行 443 → `sudo nginx -T \| grep api.你的域名` 看配置是否已加载 → 证书是否对该子域名签发 |
| 头像 404 | 确认 `UPLOADS_DIR` 与 Nginx 的 `/static/` 指向同一目录（默认 `/opt/error-learn/server/uploads`） |

## 14. 影响范围与回滚

**这次部署在你服务器上到底动了什么？**

| 项 | 内容 | 会影响原网站吗 |
| --- | --- | --- |
| **新增文件** | `/etc/systemd/system/error-learn-api.service`、`/etc/nginx/conf.d/error-learn.conf`、`/etc/nginx/ssl/api.example.com.{pem,key}`、`/opt/error-learn/**` | 不会 |
| **修改的原有文件** | **无**（不改原网站配置、不重装 Nginx） | 不会 |
| **唯一的全局动作** | `sudo systemctl reload nginx`（平滑重载） | 不会 |
| **新增监听** | `127.0.0.1:8000`（或 8080），仅本机，不对外 | 不会 |
| **新增数据库** | 独立 RDS 上的 `error_learn` 库 | 不会（不同实例） |

**想撤掉本项目（回滚）**：

```bash
# ① 摘掉 Nginx 上的本项目（立即生效，不影响原网站）
sudo rm -f /etc/nginx/conf.d/error-learn.conf
sudo nginx -t && sudo systemctl reload nginx

# ② 停掉并移除本项目服务
sudo systemctl disable --now error-learn-api
sudo rm -f /etc/systemd/system/error-learn-api.service
sudo systemctl daemon-reload

# ③ 证书（如不再需要）
~/.acme.sh/acme.sh --remove -d api.example.com
sudo rm -f /etc/nginx/ssl/api.example.com.pem /etc/nginx/ssl/api.example.com.key

# ④（可选）删除代码
sudo rm -rf /opt/error-learn
```
