## 0. 先读这一页（3 分钟，别跳过）

### 0.1 你要操作两个"窗口"，别搞混

整个部署只涉及**两个地方**，本文每一步都会用 `【在哪个窗口】` 标出来：

| 代号 | 是什么 | 长什么样 | 用来干什么 |
| --- | --- | --- | --- |
| **【控制台】** | 阿里云官网的控制台（浏览器里的网页） | 一堆按钮、菜单、表格 | 建数据库、加白名单、看实例、连服务器 |
| **【黑框】** | ECS 的「远程连接」工作台（Workbench），是一个**黑底命令行窗口** | 黑底、可以打字、提示符形如 `root@iZxxxx:~#` | **敲命令**（装软件、启动服务） |

> 一句话：**要"点鼠标"的去【控制台】，要"敲命令"的去【黑框】。**

### 0.2 术语小卡片（看不懂就回来查）

- **命令行 / 黑框**：不是图片，是要你**打字并回车**的地方。
- **`sudo`**：以管理员身份执行。你如果本来就是 `root` 登录，加不加都行。
- **路径**：文件在服务器上的"地址"，比如 `/opt/error-learn`。
- **提示符 `#` 或 `$`**：黑框最左边那一串（如 `root@iZxxxx:~#`），它后面才是你打字的地方。
- **端口**：一台服务器上不同程序的"门牌号"，比如 Nginx 用 443、我们的后端用 8000。

### 0.3 三条"保命"操作

| 要做什么 | 怎么做 |
| --- | --- |
| **粘贴命令** | 在【黑框】里用 **`Ctrl` + `Shift` + `V`**，或**点鼠标右键**（很多浏览器不支持 `Ctrl+V`） |
| **发现敲错了 / 卡住了** | 按 **`Ctrl` + `C`** 中断，回到提示符 |
| **不确定刚才成功没** | 看本文每步的 **✅ 验证点**，照着比对 |

### 0.4 本文的阅读规则

- 每一步都标了 **【在哪个窗口】** 和 **✅ 验证点**。
- **看到 ✅ 验证点通过，再进入下一步**；不通过就看 [§13 卡住了怎么办](#13-卡住了怎么办)。
- 全文命令可以整段复制，见 [附录 A：命令速查](#附录-a命令速查可整段复制)。

> **本次部署只做"新增"，不改动你已经有的网站。**
> 不重装 Nginx、不改别的网站的配置、Nginx 只"平滑重启"（`reload`）不"整体重启"（`restart`）。撤掉本项目也不会影响你原来的网站，详见 [§14](#14-影响范围与回滚)。

## 3. 第一步：登录你的云服务器（Workbench）

**这一步的目标**：在浏览器里打开一个能敲命令的【黑框】。

**【在哪个窗口】** 阿里云控制台（网页）

1. 打开阿里云官网 → 右上角登录 → 进入**控制台**。
2. 左上角搜索框输入 **`云服务器 ECS`** → 进入 ECS 控制台。
3. 左侧菜单点 **「实例与镜像」→「实例」**。
4. 在列表里找到你要用的那台服务器，点它右侧的 **「远程连接」**。
5. 弹窗里选 **「Workbench（推荐）」**（不同版本可能叫「通过 Workbench 远程连接」），点「登录」：
   - 如果提示输入密码，就填你创建 ECS 时设的密码（或点「一键登录」/「重置密码」后再登）。
6. 稍等几秒，你会看到一个**黑底窗口**。

**✅ 验证点**：黑框里出现类似下面这样一行（最后是 `#`）：

```
root@iZbp1xxxxxxxxxx:~#
```

在【黑框】里敲下面这条，回车：

```bash
whoami
```

- 看到 **`root`** → 成功，你现在是管理员，后面的命令可以不加 `sudo`。
- 看到别的内容（比如 `weij`）→ 也是正常的，**后面命令请保留开头的 `sudo`**。

## 4. 第二步：摸清服务器现状

**为什么要做**：这台服务器上已有别的网站，我们要先知道"门牌号有没有冲突"，再动手。

**【在哪个窗口】** 黑框（下面每条都逐行敲、逐行回车）

```bash
# ① 看 Nginx 版本（决定后面 HTTPS 配置怎么写）
nginx -v

# ② 看已有的网站用了哪些域名、哪些端口
sudo nginx -T | grep -E "server_name|listen"

# ③ 看已有的站点配置文件
ls -l /etc/nginx/conf.d/

# ④ 看 80 / 443 / 8000 端口分别被谁占用
sudo ss -lntp | grep -E ':(80|443|8000)\b'

# ⑤ 看 Nginx 是用哪个用户跑起来的
ps -o user= -C nginx | sort -u

# ⑥ 看有没有现成的证书工具（决定 §9 用 certbot 还是 acme.sh，二选一）
ls -d ~/.acme.sh 2>/dev/null; which certbot 2>/dev/null

# ⑦ 看内存和磁盘还剩多少
free -m; df -h /

# ⑧ 看系统发行版（决定后面用 apt 还是 dnf/yum）
grep -E "^ID=|^NAME=" /etc/os-release

# ⑨ 看 python3 版本（< 3.8 会导致后端依赖装不上，见 §7.2.1）
python3 --version

# ⑩ 看 SELinux 状态（Enforcing 时可能拦 Nginx 读文件，见 §13.3）
getenforce 2>/dev/null || echo "未启用 SELinux"
```

**怎么判断**（把结果填进下面这张表，后面要用）：

| 侦察项 | 怎么判断 | 你的结论 |
| --- | --- | --- |
| ① Nginx 版本 | 输出形如 `nginx/1.24.0`。**≥1.25.1** 与 **1.24.x** 后面写法不同 | ____________ |
| ② 已有域名 | 会列出类似 `server_name a.com;` 的多行 | ____________ |
| ③ 已有配置 | `/etc/nginx/conf.d/` 下已有哪些 `.conf` 文件 | ____________ |
| ④ **8000 是否被占** | **有输出**=被占用（说明要改用 8080）；**没输出**=空闲，用 8000 | ____________ |
| ⑤ Nginx 用户 | 常见 `www-data`（Ubuntu）或 `nginx`（CentOS） | ____________ |
| ⑥ 证书工具 | 有 certbot 就用 certbot；只有 `~/.acme.sh` 就用 acme.sh；都没有就装 certbot（**二选一，别混用**，见 §9） | ____________ |
| ⑧ **系统发行版** | `ID=alinux`/`centos`/`rhel`/`anolis` → 用 **`dnf`**；`ID=ubuntu`/`debian` → 用 **`apt`**（决定装软件的命令） | ____________ |
| ⑨ **python3 版本** | **≥ 3.8** 合格；**3.6 / 3.7** 太旧，需换新版 Python 并重建 venv（§7.2.3） | ____________ |
| ⑩ SELinux | `Enforcing` = 开着（可能拦 Nginx 读文件）；`Disabled` / `Permissive` = 不拦 | ____________ |

**✅ 验证点**：上面每条命令都执行完且**没有报错**；④ 那一项你已经明确知道 **8000 是否被占用**；⑧ 你知道该用 `dnf` 还是 `apt`。

> 小提示：第 ④ 条如果输出里出现 `users:(("nginx",...))` 并且端口是 80/443，那是**你原来的网站**，属于正常，不用管。

## 5. 第三步：把代码下载到服务器

**这一步的目标**：把项目代码从 GitHub 下载到服务器的 `/opt/error-learn` 目录。

### 5.1 ⚠️ 先在你自己的电脑上做一件事：把最新代码推上去

**为什么**：你电脑上的代码可能比 GitHub 上"新"。如果服务器从 GitHub 拉，就会拉到**旧代码**，后面会缺文件。

**【在你自己的电脑上】**（就是你现在这个项目文件夹里）执行一次推送；如果你不确定，可以直接让助手帮你执行：

```bash
git push
```

**✅ 验证点**：本地执行 `git status` 时提示 **`nothing to commit, working tree clean`** 且 `git status` 顶部没有 `ahead of 'origin/...' by N commits`（即本地没有未推送的提交）。

### 5.2 在服务器上安装 git

**【在哪个窗口】** 黑框

先看有没有：

```bash
git --version
```

- 显示 `git version x.x.x` → 已安装，**跳到 5.3**。
- 提示 `command not found` → 先按系统类型选对应命令安装：

```bash
# 看系统类型（决定用哪个包管理器）
grep -E "^ID=|^NAME=" /etc/os-release
```

| 系统（`ID=` 的值） | 包管理器 | 安装命令 |
| --- | --- | --- |
| `alinux`（阿里云 Linux）/ `centos` / `rhel` / `anolis` | `dnf`（或 `yum`） | `sudo dnf install -y git` |
| `ubuntu` / `debian` | `apt` | `sudo apt update && sudo apt install -y git` |

> ⚠️ **本教程对应的这台服务器实测为「Alibaba Cloud Linux 3（OpenAnolis Edition）」，属于 RHEL 系，没有 `apt`**——直接敲 `apt` 会报 `sudo: apt: command not found`。请统一使用 `dnf`（`yum` 也可，是 `dnf` 的兼容别名）。后文所有安装命令同理。

### 5.3 下载代码

**【在哪个窗口】** 黑框

> ⚠️ 本项目**最新代码在 `develop` 分支**（不是默认的 `master`），下面用 `-b develop` 明确指定，避免拉到旧代码。

```bash
sudo git clone -b develop https://github.com/diamondwei2026-maker/ai-error-learn.git /opt/error-learn
```

> 这会把代码放到服务器的 `/opt/error-learn` 目录（下文把这个目录叫 **项目目录**）。
> 如果这条命令报超时或 `RPC failed; curl 7 ... Connection timed out`，**别反复重试**，直接按 [§5.4](#54-下载失败怎么办实测排障) 处理。

**✅ 验证点**：敲下面这条列出目录内容：

```bash
ls /opt/error-learn
```

应当看到这些名字：**`client`、`server`、`deploy`、`.trae`**（可能还有 `.docs`、`.gitignore` 等）。

> ❗ **如果 `ls` 报 `No such file or directory`**（或你后面执行 `cd /opt/error-learn/server` 时报这个错），说明**代码根本没下载成功**——`/opt/error-learn` 这个目录不存在，**不是路径写错、也不是命令打错**。请**停止往下走**，回到本页按 [§5.4](#54-下载失败怎么办实测排障) 重新下载。

### 5.4 下载失败怎么办（实测排障）

国内 / 受限网络下 `git clone` 常见失败，报错通常长这样：

```
error: RPC failed; curl 7 Failed to connect to github.com port 443: Connection timed out
fatal: expected flush after ref listing
```

**别急着反复重试**——先按 5.4.1 诊断，再按结论选 5.4.2 / 5.4.3 / 5.4.4 绕过。

#### 5.4.1 三步快速诊断

**【在哪个窗口】** 黑框

```bash
# ① 域名能不能解析（nslookup 可能没装，用 getent 替代）
getent hosts github.com

# ② 首页能不能通（返回 HTTP/2 200 就说明握手正常）
curl -sI --connect-timeout 10 https://github.com

# ③ 看 git 到底卡在哪一步（最有价值的一条）
GIT_CURL_VERBOSE=1 GIT_TRACE=1 git clone https://github.com/diamondwei2026-maker/ai-error-learn.git /tmp/git-test 2>&1 | tail -40
```

**怎么判断**：

| 现象 | 含义 |
| --- | --- |
| ① 能输出 IP、② 返回 `HTTP/2 200` | 说明 **DNS 和 HTTPS 握手都正常**，不是"连不上" |
| ③ 卡在 `POST /.../git-upload-pack` 后长时间无响应，约 30 秒后连接被关闭 | **本教程实测的根因**，见下 |

> **实测结论（重要）**：这台服务器能做到「`curl https://github.com` 返回 200、列 ref 列表也正常」，但一发 `POST git-upload-pack`（真正拉代码包体的请求）就**挂起约 30 秒，随后连接被强制关闭，且短时间内重连同一 IP 也会超时**。这是典型的**链路中间设备（DPI）对 git 传输做拦截**——不是你的配置错，**反复重试、调 `http.postBuffer` 都无效**，必须**换通道绕过**。

#### 5.4.2 方案一：用国内镜像前缀克隆（先用这条试）

在原始 GitHub 地址前拼一个镜像前缀即可，仓库地址本身不变。**本教程对应服务器实测：`gh-proxy.com` 域名可用**（其余可依次尝试）：

**【在哪个窗口】** 黑框

```bash
# 本机实测可用（推荐先用这条）：
sudo git clone -b develop https://gh-proxy.com/https://github.com/diamondwei2026-maker/ai-error-learn.git /opt/error-learn

# 上面的失败时，依次换下面这些域名：
sudo git clone -b develop https://ghproxy.com/https://github.com/diamondwei2026-maker/ai-error-learn.git /opt/error-learn
sudo git clone -b develop https://mirror.ghproxy.com/https://github.com/diamondwei2026-maker/ai-error-learn.git /opt/error-learn
sudo git clone -b develop https://gitclone.com/github.com/diamondwei2026-maker/ai-error-learn.git /opt/error-learn
```

> 说明：这类**公共代理只支持公开仓库**。本项目实测为**公开仓库**可直接用；若是私有仓库，代理会返回 404，请走 5.4.3 或 5.4.4。
> 镜像域名可用性随时会变，某个报错就换下一个；若连着几个都不行，直接跳到 5.4.3。

**✅ 验证点**：`ls /opt/error-learn` 能看到 `client server deploy .trae`。

#### 5.4.3 方案二：打包下载（**本机实测最稳**）

不跑 git 传输，直接用 HTTP 把源码压缩包拉下来。**本教程对应服务器实测这条最稳**（`gh-proxy.com` + `develop` 分支，实测返回 `HTTP:200 size:913217`）。

**【在哪个窗口】** 黑框

**第 1 步：下载 zip，并打印状态码确认是否真的下成功**

```bash
# -w 会打印 HTTP 状态码和实际下载字节数，是判断"下没下成功"的关键
curl -L -o /tmp/error-learn.zip -w "HTTP:%{http_code}  size:%{size_download}\n" https://gh-proxy.com/https://github.com/diamondwei2026-maker/ai-error-learn/archive/refs/heads/develop.zip
```

- 看到 **`HTTP:200 size:` 后是一个较大的数字**（本项目约 91 万字节 / 约 900 KB）→ 下载成功，继续第 2 步。
- 看到 **`size:0`** 或 **`HTTP:404`** / **`HTTP:000`** → 下载失败：`404` 多为私有仓库，`000` 或卡住为镜像不可用。换成 [§5.4.2](#542-方案一用国内镜像前缀克隆先用这条试) 里的其它镜像域名重试，只把开头的域名换掉，后面 URL 不变。

> 两个易踩的点：
> ① **分支名**——本项目用 **`develop`**；换别的项目时把 URL 里的 `develop` 换成它的默认分支（常见 `main` 或 `master`）。
> ② **命令换行**——命令结尾的 `\` 是*换行续行符*，整条写成一行也完全可以；若用 `\`，它**必须是该行最后一个字符，后面不能有空格**，否则会报错。

**第 2 步：解压并改名到项目目录**

```bash
sudo dnf install -y unzip                                    # 若没装 unzip
sudo unzip -o /tmp/error-learn.zip -d /opt                   # 解压到 /opt
ls /opt                                                      # 看一眼解压出的目录名
sudo mv /opt/ai-error-learn-develop /opt/error-learn         # develop 分支解压出的目录名就是它
```

> 若 `ls /opt` 显示的目录名不是 `ai-error-learn-develop`，把上面 `mv` 里的源名换成你实际看到的那个。

**✅ 验证点**：`ls /opt/error-learn` 能看到 `client server deploy .trae`。

> ⚠️ 注意：打包下载得到的是**某一分支的快照，不含 `.git` 目录**——部署运行没问题，但**以后不能在这台服务器上用 `git pull` 更新代码**。若需频繁更新，请改用 5.4.2 的镜像克隆方式（同样记得 `-b develop`）。

#### 5.4.4 方案三：改用 SSH（含 443 端口）

拦截针对的是 HTTPS 的 git 流量特征，SSH 是另一套流量，常能绕过。先测 22 端口：

```bash
ssh -T git@github.com
```

若 22 端口超时，改用 **443 端口的 SSH**——编辑 `~/.ssh/config`：

```
Host github.com
  Hostname ssh.github.com
  Port 443
  User git
```

再执行：

```bash
ssh -T github.com
git clone git@github.com:diamondwei2026-maker/ai-error-learn.git /opt/error-learn
```

> 前置条件：已在 GitHub 账号里添加过你的 SSH 公钥（本地有 `~/.ssh/id_rsa.pub` 或 `id_ed25519.pub`）。

#### 5.4.5 补充：git 传输调优（仅对"传一半断流"有效）

若诊断显示是**大包体传到中途断**（而不是"请求一发出去就被掐"），可尝试：

```bash
git config --global http.version HTTP/1.1
git config --global http.postBuffer 524288000
git config --global http.lowSpeedLimit 0
git config --global http.lowSpeedTime 999999

# 或改用浅克隆，减小传输量
```

## 7. 第五步：部署后端程序

**这一步的目标**：让后端的"识别服务"在服务器上跑起来，并能被 Nginx 访问。

**【在哪个窗口】** 黑框

### 7.1 说明：关于"端口"

- 如果 §4 侦察到 **8000 空闲** → 全文用 **8000**。
- 如果 **8000 被占用** → 改用 **8080**；后面凡是出现 `8000` 的地方，都要换成 `8080`（本文会给出一键脚本自动处理）。

### 7.2 安装 Python 依赖

#### 7.2.1 先检查 Python 版本（关键，别跳过）

**为什么**：本项目要求 **Python ≥ 3.8**（`fastapi>=0.110` / `sqlalchemy>=2.0` / `pytest>=8.0`）。服务器系统自带的 `python3` 可能很旧（**实测本教程对应的阿里云 Linux 3 上是 Python 3.6**），用它建的 venv **装不上本项目依赖，后端起不来**。

【黑框】先看版本：

```bash
python3 --version
```

| 结果 | 结论 |
| --- | --- |
| `Python 3.8` ~ `3.12` | 合格，跳到 §7.2.2 |
| `Python 3.6` / `3.7`（或更低） | **太旧，必须换新版 Python**，见 §7.2.3 |

#### 7.2.2 版本合格：正常安装

```bash
# 只装 Python 相关工具，不装/不升级 Nginx（服务器上已有）
# 按系统选一行执行（本教程对应服务器为 Alibaba Cloud Linux 3 / RHEL 系 → 用第一行）：
sudo dnf install -y python3 python3-pip curl                # 阿里云 Linux / CentOS / RHEL
# sudo apt update && sudo apt install -y python3 python3-pip curl   # Ubuntu / Debian

cd /opt/error-learn/server
python3 -m venv .venv
./.venv/bin/python -m pip install --upgrade pip
./.venv/bin/python -m pip install -r requirements.txt
```

#### 7.2.3 Python 太旧（3.6 / 3.7）时：装新版并重建 venv

**症状**：`./.venv/bin/python -m pip install --upgrade pip` 只回一句
`Requirement already satisfied: pip in ./.venv/lib/python3.6/site-packages (21.3.1)`。

**原因**：路径里的 `python3.6` 说明这个 venv 是 **Python 3.6** 建的；而 `21.3.1` 是**最后一个支持 Python 3.6 的 pip 版本**，更高版本都要求 Python ≥ 3.7，所以“没有更新的能装”，pip 才回 `already satisfied`。**这不是 pip 坏了、也不是升级失败——根因是 Python 太旧**，光升 pip 无效，必须换 Python。

【黑框】装新版 Python（推荐 3.11，RHEL 系实测可直接装）：

```bash
sudo dnf list available "python3.1*"                  # 先看仓库有没有
sudo dnf install -y python3.11 python3.11-devel      # 列表里有 python3.11 就用这条
# Ubuntu/Debian：sudo apt update && sudo apt install -y python3.11 python3.11-venv
python3.11 --version                                 # ✅ 应显示 Python 3.11.x
```

> 若 `dnf list` 里**没有** `python3.11`，说明该源没有，需换源或编译安装——**先停下告诉助手，别自己乱试**。

删除旧 venv，用新 Python 重建（旧 venv 是 3.6 的，留着无用）：

```bash
cd /opt/error-learn/server
rm -rf .venv
python3.11 -m venv .venv
./.venv/bin/python -m pip install --upgrade pip
./.venv/bin/python -m pip install -r requirements.txt
```

**✅ 验证点**：

```bash
./.venv/bin/python --version         # 显示 3.11.x（不再是 3.6）
./.venv/bin/python -m pip --version  # 显示较新的 pip（如 25.x / 26.x，不再是 21.3.1）
```

> ⚠️ **脚本提醒**：`deploy/deploy.sh` 里是 `python3 -m venv .venv`，只在“没有 venv 时”才建、**不校验 Python 版本**，会沿用旧的坏 venv。故**务必先做 §7.2.1 检查**，装好新版 Python 并 `rm -rf .venv` 后，再跑脚本。

> ⚠️ **RHEL 系（含阿里云 Linux 3）没有 `python3-venv` 这个包**——那是 Debian/Ubuntu 的叫法，`venv` 由 `python3` 自带，装 `python3` 即可。只有在创建虚拟环境时报缺 `ensurepip` 时，才补装：`sudo dnf install -y python3-devel`。

**MySQL 8 特别注意**（必做，否则连不上数据库）：

```bash
./.venv/bin/python -m pip install "PyMySQL[rsa]"
```

**✅ 验证点**：最后一条命令以 `Successfully installed ...` 结尾，且没有红色 `ERROR`。

### 7.3 写配置文件 `.env`

这个文件存放密钥和数据库地址，**服务器上本来没有，需要你新建**。

【黑框】先复制模板：

```bash
cp /opt/error-learn/deploy/env.production.example /opt/error-learn/server/.env
```

然后编辑它。**小白推荐用 `nano`**（比 `vi` 友好）：

```bash
nano /opt/error-learn/server/.env
```

> ⚠️ **若报 `nano: command not found`**：阿里云 Linux 3（RHEL 系）最小化安装**默认不带 `nano`**。两种办法——① 装一个：`sudo dnf install -y nano`；② 改用系统自带的 `vi`：`sudo vi /opt/error-learn/server/.env`（按 `i` 进编辑，改完按 `Esc`，再输 `:wq` 回车保存退出）。

进入后是一个文本编辑器窗口，按键盘方向键移动光标，改下面这几个值：

| 要改的项 | 改成什么 |
| --- | --- |
| `VISION_API_KEY=` | 你的 AI 识别模型密钥 |
| `WECHAT_APP_SECRET=` | 微信小程序 AppSecret（**别用开发时的值**） |
| `JWT_SECRET=` | 一串随机字符，可先用 `openssl rand -hex 32` 生成后粘贴 |
| `DATABASE_URL=` | **必须是一整条**连接串：`mysql+pymysql://账号:密码@RDS内网地址:3306/error_learn?charset=utf8mb4`（把"账号/密码/RDS内网地址"换成 §6 里的真实值） |
| `UPLOADS_DIR=` | 保持 `/opt/error-learn/server/uploads` 不变 |

> ⚠️ **`DATABASE_URL` 是最容易填错的一项**：**只填主机名**（如 `rm-bp1xxxx.mysql.rds.aliyuncs.com`）是**不行**的——后端起不来，日志报 `sqlalchemy.exc.ArgumentError: Could not parse SQLAlchemy URL from given URL string`。正确 / 错误对比：
>
> ```
> ❌ 错：rm-bp1xxxx.mysql.rds.aliyuncs.com
> ✅ 对：mysql+pymysql://user:pass@rm-bp1xxxx.mysql.rds.aliyuncs.com:3306/error_learn?charset=utf8mb4
> ```
>
> 若密码含 `@` `#` `:` 等特殊字符，需做 URL 编码（如 `@` → `%40`）。

**`nano` 怎么保存和退出（很重要）**：

1. 改完后按 **`Ctrl` + `O`**（字母 O），再按 **回车** → 保存。
2. 按 **`Ctrl` + `X`** → 退出，回到黑框。

> **备选（完全不想用编辑器）**：可以整段粘贴重建文件，见 [附录 A-7.3](#73-写配置文件-env-的整段粘贴法)。

**✅ 验证点**：黑框回到提示符后，执行下面这条，应能看到你填的数据库连接串：

```bash
grep DATABASE_URL /opt/error-learn/server/.env
```

### 7.4 安装并启动服务（systemd）

先确认服务要以哪个用户运行（**RHEL 系通常是 `nginx`，而不是 `www-data`**）：

```bash
ps -o user= -C nginx | sort -u
```

把模板里的占位符和运行用户一并替换，再写入 systemd 目录（**已合成一行，避免 `\` 换行出错**；若用 8080，把 `--port 8000` 一并替换）：

```bash
# 把下面两处 nginx 换成上一条命令查到的用户（阿里云 Linux 3 一般是 nginx）
sudo sed -e "s#<DEPLOY_DIR>#/opt/error-learn#g" -e "s#User=www-data#User=nginx#g" -e "s#Group=www-data#Group=nginx#g" /opt/error-learn/deploy/systemd/error-learn-api.service | sudo tee /etc/systemd/system/error-learn-api.service >/dev/null
```

> ⚠️ **为什么必须替换 `User=`**：服务模板默认 `User=www-data`——那是 Debian/Ubuntu 的叫法。在阿里云 Linux 3 上**根本没有 `www-data` 这个用户**，systemd 会直接报 **`status=217/USER`**（进程压根没启动，日志里也看不到任何 Python 报错）。把上面 `nginx` 换成你查到的那位即可；实在不想折腾就改用 `root`。

给运行用户开 `uploads` 目录的写权限（否则启动到「建头像目录」这一步会报 `PermissionError`）：

```bash
sudo mkdir -p /opt/error-learn/server/uploads
sudo chown -R nginx:nginx /opt/error-learn/server/uploads     # 同样把 nginx 换成你的运行用户
```

然后重新加载并启动：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now error-learn-api
```

**✅ 验证点**（两条都要通过）：

```bash
# ① 服务状态：应看到绿色的 active (running)
sudo systemctl status error-learn-api

# ② 本机自测：应返回 {"status":"ok"}
curl http://127.0.0.1:8000/api/v1/health
```

- ① 看到 **`active (running)`** → 服务在跑。
- ② 看到 **`{"status":"ok"}`** → 后端正常（用 8080 的话把命令里的 8000 换掉）。
- 如果失败：执行 `sudo journalctl -u error-learn-api -n 50` 看最后 50 行报错，多为 `.env` 里 `JWT_SECRET` / `DATABASE_URL` 没填好。

### 7.5 省事通道：一条命令搞定（可选）

如果你跳过了 7.2~7.4，也可以用仓库里的一键脚本（它会把上面的步骤按顺序做完）：

```bash
# 端口 8000
sudo DEPLOY_DIR=/opt/error-learn DOMAIN=api.example.com bash /opt/error-learn/deploy/deploy.sh

# 端口 8000 被占时，改用 8080（脚本会先检查端口是否空闲）
sudo DEPLOY_DIR=/opt/error-learn DOMAIN=api.example.com PORT=8080 bash /opt/error-learn/deploy/deploy.sh
```

> 脚本**不会**帮你申请 HTTPS 证书（证书见 §9），也不会改动你原来的网站。

## 8. 第六步：接上 Nginx（新增一个子域名站点）

**这一步的目标**：让 `https://api.你的域名` 转发到后端。**只新增一个文件，不动原有网站。**

**【在哪个窗口】** 黑框

### 8.1 放置站点配置

把模板里的 3 处占位（域名、证书路径）替换成你的真实值，然后写入 Nginx 配置目录：

```bash
sudo mkdir -p /etc/nginx/ssl
sudo sed \
  -e "s#api.example.com#api.example.com#g" \
  -e "s#/etc/nginx/ssl/api.example.com.pem#/etc/nginx/ssl/api.example.com.pem#g" \
  -e "s#/etc/nginx/ssl/api.example.com.key#/etc/nginx/ssl/api.example.com.key#g" \
  /opt/error-learn/deploy/nginx/error-learn.conf \
  | sudo tee /etc/nginx/conf.d/error-learn.conf >/dev/null
```

> 上面三行的 `api.example.com` 请**全部换成你的真实子域名**（比如 `api.mysite.com`）。
> 如果后端端口改成了 8080，再补一条：
> ```bash
> sudo sed -i "s#127.0.0.1:8000#127.0.0.1:8080#g" /etc/nginx/conf.d/error-learn.conf
> ```

### 8.2 校验并加载（只 reload，不 restart）

```bash
sudo nginx -t
sudo systemctl reload nginx
```

**✅ 验证点**：

- `nginx -t` 输出应包含 **`syntax is ok`** 和 **`test is successful`**。
- 若报错，多半是 **Nginx 版本与 HTTP/2 写法不符**：模板默认 `http2 on;`（需要 Nginx ≥ 1.25.1）；若你的版本是 **1.24.x**，请编辑 `/etc/nginx/conf.d/error-learn.conf`，把这行改成 `listen 443 ssl http2;` 并删掉 `http2 on;`。

> **为什么只能 `reload` 不能 `restart`？** `reload` 是"平滑重载"，不会打断你原来网站的访问；`restart` 会让 Nginx 整个重启，**你原来的网站会瞬间打不开**。共享服务器上请始终用 `reload`。

### 8.3 顺手加个 DNS 解析（在域名服务商处）

【控制台】到你的**域名解析**（阿里云叫「云解析 DNS」）里，给主域名加一条记录：

- 类型：**A**
- 主机记录：`api`（这样就是 `api.你的域名`）
- 记录值：你的 **ECS 公网 IP**

**✅ 验证点**：过几分钟后，在【黑框】执行（把域名换成你的）：

```bash
curl -v https://api.example.com/api/v1/health
```

看到 `{"status":"ok"}` 即成功（此时若证书还没好会报证书错误，属正常，先做 §9）。

### 8.4 常见坑：报"证书域名不匹配"

如果你用 `curl` 访问 `https://api.你的域名` 时看到：

```
SSL: no alternative certificate subject name matches target host name 'api.example.com'
curl: (51) SSL: no alternative certificate subject name matches target host name
```

**这不是证书没办，而是"这个域名在 Nginx 里没配对"**：请求没匹配到本站的 `server_name`，于是落到了**兜底默认站**（`server_name _;`），返回的是**别的站点**的证书，所以域名对不上。

**一步定位**（【黑框】执行）：

```bash
sudo nginx -T 2>/dev/null | grep -nE "server_name|ssl_certificate"
```

- **搜不到** `api.你的域名` → 本站压根没配 → 回到 [§8.1](#81-放置站点配置) 重新放置配置。
- **搜得到**，但该站点的 `ssl_certificate` 指向的是**别的域名**的证书 → 证书路径写错 → 按 [§9.4](#94-最后一步让-nginx-用上证书并验收) 修正，或重新签发本站证书。
- 若 `sudo nginx -t` 报 `cannot load certificate ... No such file or directory`，说明**证书文件还不存在** → 先办证书（§9），再配本站。

## 9. 第七步：申请 HTTPS 证书

**先判断：用哪种证书工具？** 看 §4 勘察第 ⑥ 项的结论：

| §4 侦察结果 | 用哪个工具 | 去哪一节 |
| --- | --- | --- |
| 已有 `certbot`（`which certbot` 有输出） | **certbot**（推荐） | [§9.2](#92-方案-acertbot推荐) |
| 已有 `~/.acme.sh` | acme.sh | [§9.3](#93-方案-bacmesh) |
| 两个都没有 | 装 **certbot** | [§9.2](#92-方案-acertbot推荐) |

> ⚠️ **不要两套工具混用**。同一台服务器上用一套就行：若这台机器原来就用 certbot 管证书（`/etc/letsencrypt/` 下有站点、`systemctl list-timers | grep certbot` 有定时任务），就**统一用 certbot**，不要再装 acme.sh，免得续期任务互相打架。

**为什么优先用 DNS 验证**：你的 **80 端口已被原网站占用**，而另一种方式 HTTP-01 需要 80 端口做校验，在共享服务器上**经常失败**（见 [§9.2.2](#922-不推荐certbot---nginxhttp-01以及-403-坑) 的 403）。DNS 验证不占端口、不依赖站点配置，最稳。

**【在哪个窗口】** 黑框

---

### 9.2 方案 A：certbot（推荐）

#### 9.2.1 推荐做法：DNS-01 手动验证（最稳，绕开 80 端口）

一条命令，然后按提示操作：

```bash
sudo certbot certonly --manual --preferred-challenges dns -d api.example.com
```

它会**暂停**并让你加一条 TXT 记录：

```
Please deploy a DNS TXT record under the name:
_acme-challenge.api.example.com.

with the following value:
xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx     ← 把这串记下来
```

**这时先不要按回车！** 按下面三步走完再回车：

1. 【控制台】→「云解析 DNS」→ 你的主域名 → **添加记录**：
   - 记录类型：**TXT**
   - **主机记录：`_acme-challenge.api`** ← ⚠️ 不是只填 `_acme-challenge`。规则是"完整记录名去掉主域名"，即 `_acme-challenge.api.example.com` 去掉 `.example.com` 后剩 `_acme-challenge.api`
   - 记录值：粘贴上面那串
2. **先确认记录已生效**（服务器没装 `dig`/`nslookup` 时用这条 curl 直接问 DNS）：
   ```bash
   curl -s "https://223.5.5.5/resolve?name=_acme-challenge.api.example.com&type=TXT"
   ```
   返回的 `Answer` 里能看到那串值 = 生效。
   （想用命令行的，`sudo dnf install -y bind-utils` 后执行 `dig +short TXT _acme-challenge.api.example.com`）
3. 看到值了，切回 certbot 窗口**按回车**。

**✅ 验证点**：出现 `Successfully received certificate`；证书在：

```
/etc/letsencrypt/live/api.example.com/fullchain.pem
/etc/letsencrypt/live/api.example.com/privkey.pem
```

```bash
sudo ls -l /etc/letsencrypt/live/api.example.com/
```

> ⚠️ **重跑要重新对值**：这个方式**每次重新执行都会生成一串新的值**，旧的立刻作废。"值还没生效就回车 → 报 NXDOMAIN"是新手最常踩的坑。牢记顺序：**先在阿里云改好 TXT → 确认生效 → 再回 certbot 回车**。
>
> ⚠️ 手动 DNS 方式**不能自动续期**，证书到期前要手动重来（见 [§9.2.4](#924可选让-certbot-自动续期) 彻底解决）。

#### 9.2.2 不推荐：`certbot --nginx`（HTTP-01），以及 403 坑

```bash
sudo certbot --nginx -d api.example.com --redirect
```

它会自动改 Nginx、加 HTTPS、自动续期，看着很方便，但在**共享 80 端口的服务器上常失败**：

```
Detail: ... Invalid response from http://api.example.com/.well-known/acme-challenge/xxx: 403
```

**403 的含义与原因**（能拿到 403 说明请求**已经到达 Nginx**，不是 DNS / 端口问题）：

- 该域名的请求**落到了 `server_name _;` 兜底站**（即这个域名在 Nginx 里没配到位），而兜底站配置里常有 `location ~ /\. { deny all; }` 这类**正则规则，拒绝对 `.well-known` 的访问** → 403。
- 根因就是**顺序反了**：应**先按 §8 把本站配好，再签证书**。

**遇到 403 怎么办**：别跟 80 端口继续耗，**直接改用 [§9.2.1](#921-推荐做法dns-01-手动验证最稳绕开-80-端口) 的 DNS-01**，一次通过。若坚持用 HTTP-01，需在**匹配本站的 server 块**里加一条**跳过正则**的 location：

```nginx
location ^~ /.well-known/acme-challenge/ {
    root /var/www/acme;
}
```

```bash
sudo nginx -t && sudo systemctl reload nginx
sudo mkdir -p /var/www/acme
sudo certbot certonly --webroot -w /var/www/acme -d api.example.com
```

#### 9.2.3 certbot 常见报错

| 报错 | 原因 / 处理 |
| --- | --- |
| `Another instance of Certbot is already running.` | 上次 certbot 没退干净，**锁文件残留**。先 `ps aux \| grep certbot \| grep -v grep` 看还有没有进程（有就 `sudo kill -9 <PID>`），再删锁：`sudo rm -f /var/lib/letsencrypt/.certbot.lock`，然后重跑 |
| `NXDOMAIN looking up TXT for _acme-challenge...` | TXT 记录没加 / 加错位置（漏了子域名前缀）/ 还没生效就回车了。见 [§9.2.1](#921-推荐做法dns-01-手动验证最稳绕开-80-端口) |
| `Invalid response from ... 403` | 见 [§9.2.2](#922-不推荐certbot---nginxhttp-01以及-403-坑) |
| `Could not find a server block` | 该域名在 Nginx 里没有对应 server 块，先做 §8 |

#### 9.2.4（可选）让 certbot 自动续期

手动 DNS 方式不能自动续期。装阿里云 DNS 插件后可全自动：

```bash
sudo pip3 install certbot-dns-aliyun
sudo tee /root/aliyun.ini >/dev/null <<'EOF'
dns_aliyun_access_key = 你的AccessKeyId
dns_aliyun_access_key_secret = 你的AccessKeySecret
EOF
sudo chmod 600 /root/aliyun.ini
sudo certbot certonly --dns-aliyun \
  --dns-aliyun-credentials /root/aliyun.ini \
  -d api.example.com
```

之后 certbot 自带的 systemd 定时任务会自动续期，无需手动。

### 9.3 方案 B：acme.sh

（若 §4 侦察发现服务器**已有** `~/.acme.sh`，用这一套。）

先准备「阿里云 DNS 的 AccessKey」：到【控制台】右上角头像 →「AccessKey 管理」→ 创建一个（建议只给 DNS 权限），记下 `AccessKeyId` 和 `AccessKeySecret`。

```bash
# 1) 安装 acme.sh（若 §4 侦察到已存在则跳过）
curl https://get.acme.sh | sh -s email=你的邮箱@example.com

# 2) 设置默认 CA
~/.acme.sh/acme.sh --set-default-ca --server letsencrypt

# 3) 用阿里云 DNS 自动签发（把下面两个值换成你的 AccessKey，域名换成你的）
export Ali_Key="你的AccessKeyId"
export Ali_Secret="你的AccessKeySecret"
~/.acme.sh/acme.sh --issue --dns dns_ali -d api.example.com

# 4) 把证书装到 Nginx 目录（续签后自动 reload）
sudo mkdir -p /etc/nginx/ssl
~/.acme.sh/acme.sh --install-cert -d api.example.com \
  --key-file       /etc/nginx/ssl/api.example.com.key \
  --fullchain-file /etc/nginx/ssl/api.example.com.pem \
  --reloadcmd      "sudo systemctl reload nginx"

# 5) 查看证书有效期
openssl x509 -in /etc/nginx/ssl/api.example.com.pem -noout -subject -dates
```

**✅ 验证点**：第 5 条能看到 `subject=CN = api.example.com` 和两行日期。

> acme.sh 会自动加一个定时任务去续期，不用你操心。

### 9.4 最后一步：让 Nginx 用上证书并验收

**证书必须先在位，再让 Nginx 引用它** —— 否则 `nginx -t` 会报 `cannot load certificate ... No such file or directory`，配置加载不进去，站点也就等于没配（这正是"证书域名不匹配"最常见的前因）。

- **用 acme.sh（证书在 `/etc/nginx/ssl/`）**：直接用 §8 生成的配置即可。
- **用 certbot（证书在 `/etc/letsencrypt/live/`）**：把 §8 的配置换成下面这版（注意 HTTP/2 写法：Nginx ≥1.25.1 用 `http2 on;`；**1.24.0 必须用 `listen 443 ssl http2;`**）：

```bash
sudo tee /etc/nginx/conf.d/error-learn.conf >/dev/null <<'EOF'
server {
    listen 80;
    listen [::]:80;
    server_name api.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name api.example.com;

    ssl_certificate     /etc/letsencrypt/live/api.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/api.example.com/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;

    client_max_body_size 20m;

    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }

    location /static/ {
        alias /opt/error-learn/server/uploads/;
        expires 7d;
        add_header Cache-Control "public";
        try_files $uri =404;
    }
}
EOF

sudo nginx -t && sudo systemctl reload nginx
```

> ⚠️ 若 Nginx 是 ≥1.25.1，把 `listen 443 ssl http2;` 改成 `listen 443 ssl;` 并另起一行写 `http2 on;`。

**最终验收**：

```bash
curl -v "https://api.example.com/api/v1/health"
```

**✅ 验证点**：证书段显示 `subject: CN=api.example.com`，末尾返回 `{"status":"ok"}`。

> 💡 命令里的网址一定要用**双引号** `"` 包起来，**不要用反引号** `` ` ``（反引号在命令行里是"执行命令"的意思，会出错）。

| `certbot` 报 `NXDOMAIN looking up TXT for _acme-challenge...` | TXT 记录没加 / 主机记录填错（漏了子域名前缀）/ 还没生效就回车。见 [§9.2.1](#921-推荐做法dns-01-手动验证最稳绕开-80-端口)（注意**重跑值会变**） |

**想撤掉本项目（回滚）**：

```bash
# ④（可选）删除代码
```

```bash
# 卡住/报错时：见 §9.2.3（如删锁文件 /var/lib/letsencrypt/.certbot.lock）
```

**A-5B acme.sh（服务器已有 `~/.acme.sh` 时用，见 §9.3）：**

```bash
curl https://get.acme.sh | sh -s email=你的邮箱@example.com
~/.acme.sh/acme.sh --set-default-ca --server letsencrypt
export Ali_Key="你的AccessKeyId"
export Ali_Secret="你的AccessKeySecret"
~/.acme.sh/acme.sh --issue --dns dns_ali -d api.example.com
sudo mkdir -p /etc/nginx/ssl
~/.acme.sh/acme.sh --install-cert -d api.example.com \
  --key-file       /etc/nginx/ssl/api.example.com.key \
  --fullchain-file /etc/nginx/ssl/api.example.com.pem \
  --reloadcmd      "sudo systemctl reload nginx"
openssl x509 -in /etc/nginx/ssl/api.example.com.pem -noout -subject -dates
```

## 附录 B：术语小词典

| 名词 | 一句话解释 |
| --- | --- |
| **命令行 / 黑框** | 让你打字下命令的黑色窗口，不是网页 |
| **SSH / 远程连接** | 从你的电脑"远程操控"服务器的方式 |
| **Workbench** | 阿里云提供的网页版远程连接工具，不用装软件 |
| **sudo** | 以管理员身份运行某条命令 |
| **路径** | 文件在服务器上的地址，如 `/opt/error-learn` |
| **端口** | 程序的"门牌号"，如网站用 443、本项目后端用 8000 |
| **Nginx** | 网站入口/转发程序，负责把域名分给不同网站 |
| **reload / restart** | 平滑重载（不断线）/ 整体重启（会短暂中断） |
| **systemd** | Linux 的"服务管家"，能让程序开机自启、挂了自动拉起 |
| **venv** | Python 的"独立小环境"，避免和系统里的 Python 打架 |
| **白名单** | 数据库的"门禁名单"，只有名单里的 IP 才能连 |
| **DNS 解析** | 把域名指向你的服务器 IP 的记录 |
| **备案** | 国内网站/小程序上线的合规要求，在阿里云办理 |
