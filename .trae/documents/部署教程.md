# 错题本小程序 —— 部署教程

> 目标形态：**阿里云 ECS 自建后端 + 云 RDS MySQL 8.0 + 已备案子域名 HTTPS + 微信小程序前端**
> 本教程为纯操作手册，按章节从上到下执行即可完成上线。
> 校对日期：2026-10-15（对应当期官方规则）

---

## 0. 前置三件事（动手前必须完成）

| # | 事项 | 说明 |
| --- | --- | --- |
| 1 | **域名 ICP 备案** | 域名须已完成工信部备案，否则无法作为小程序合法域名，也无法正常对外提供 HTTPS 服务 |
| 2 | **小程序备案** | 2023-09-04 起，未完成**小程序备案**的小程序不可上架，请在微信公众平台完成 |
| 3 | **ECS 与 RDS 同地域同 VPC** | 二者须在同一地域、同一 VPC，RDS 才能通过**内网地址**被 ECS 访问（更安全、更低延迟） |

另需提前准备：ECS 实例（建议 2C2G 起）、RDS MySQL 8.0 实例、一个可解析的已备案子域名（下文统一以 `api.example.com` 代指）。

## 1. 目标架构

```
微信小程序
   │  HTTPS（request / uploadFile / downloadFile）
   ▼
[ Nginx on ECS :443 ]  ← 已备案域名 + SSL 证书
   │  proxy_pass 127.0.0.1:8000
   ▼
[ uvicorn / FastAPI :8000 ]  ← systemd 守护 error-learn-api
   │                        
   ├─→ 阿里云 RDS MySQL 8.0（内网，mysql+pymysql）
   └─→ 多模态识别模型（OpenAI 兼容 /chat/completions）
静态资源：/static/ → Nginx alias → UPLOADS_DIR（头像）
```

**关键事实（与仓库代码一致）**

| 项 | 值 | 来源 |
| --- | --- | --- |
| 健康检查 | `GET /api/v1/health` → `{"status":"ok"}` | `server/app/main.py` |
| 后端监听 | `127.0.0.1:8000` | systemd / uvicorn |
| 业务路由前缀 | `/api/v1` | `server/app/main.py` |
| 静态资源挂载 | `/static` → `UPLOADS_DIR`（默认 `server/uploads`） | `server/app/main.py` / `config.py` |
| 前端构建 | `npm run build:weapp`（产物 `client/dist/`） | `client/package.json` |
| 前端 API 基址 | 构建期 `TARO_APP_API_BASE` 注入 | `client/src/constants/index.ts` |
| 小程序 AppID | `wx683110d829c1f0f9` | `client/project.config.json` |
| 单图上限 | 10MB（`VISION_MAX_IMAGE_BYTES`） | `server/app/config.py` |

## 2. 后端部署（ECS）

### 2.1 拉取代码

```bash
sudo mkdir -p /opt/error-learn && sudo chown -R "$USER":"$USER" /opt/error-learn
git clone <仓库地址> /opt/error-learn      # 或先 clone 再移动到该目录
cd /opt/error-learn
```

约定部署根目录为 `/opt/error-learn`（下文 `<DEPLOY_DIR>` 即指此目录）。

### 2.2 创建虚拟环境并安装依赖

```bash
sudo apt update && sudo apt install -y python3 python3-venv python3-pip nginx curl

cd /opt/error-learn/server
python3 -m venv .venv
./.venv/bin/python -m pip install --upgrade pip
./.venv/bin/python -m pip install -r requirements.txt
```

**MySQL 8 特别注意**：MySQL 8 默认使用 `caching_sha2_password` 认证，需要额外的 `cryptography` 依赖，请补装：

```bash
./.venv/bin/python -m pip install "PyMySQL[rsa]"
```

### 2.3 写入生产环境变量

```bash
cp /opt/error-learn/deploy/env.production.example /opt/error-learn/server/.env
chmod 600 /opt/error-learn/server/.env
vi /opt/error-learn/server/.env      # 按注释逐项填写
```

必须填写的关键项：

| 键 | 说明 |
| --- | --- |
| `VISION_API_KEY` | 多模态识别模型密钥 |
| `WECHAT_APP_SECRET` | 微信小程序 AppSecret（从公众平台获取，**勿复用开发值**） |
| `JWT_SECRET` | 随机长字符串，生成：`openssl rand -hex 32` |
| `DATABASE_URL` | RDS 连接串：`mysql+pymysql://账号:密码@RDS内网地址:3306/error_learn?charset=utf8mb4` |
| `UPLOADS_DIR` | 静态资源目录，须与 Nginx `location /static/` 的 alias 一致 |

**RDS 侧**：在 RDS 控制台把 ECS 的**内网 IP** 加入白名单，并确认已创建库 `error_learn`。

### 2.4 安装 systemd 守护

```bash
sudo sed "s#<DEPLOY_DIR>#/opt/error-learn#g" \
  /opt/error-learn/deploy/systemd/error-learn-api.service \
  | sudo tee /etc/systemd/system/error-learn-api.service >/dev/null

sudo systemctl daemon-reload
sudo systemctl enable --now error-learn-api
sudo systemctl status error-learn-api
```

查看日志：

```bash
journalctl -u error-learn-api -f
```

本机自检：

```bash
curl http://127.0.0.1:8000/api/v1/health      # 期望 {"status":"ok"}
```

> 若服务以 `www-data` 运行，请确保该用户对 `/opt/error-learn/server` 与 `UPLOADS_DIR` 有读写权限：
> `sudo chown -R www-data:www-data /opt/error-learn/server/uploads`

## 3. Nginx 与 HTTPS

### 3.1 证书策略（三选一，推荐 acme.sh）

| 方案 | 说明 |
| --- | --- |
| **① acme.sh + DNS-01（推荐）** | DNS 验证不占用 80 端口，绕开被现有站点占用的 80；支持自动续签 |
| ② 阿里云控制台免费证书 | 现名「个人测试证书」，**有效期 90 天且不支持自动续期**，需人工轮换；作为备选 |
| ③ 复用已有通配符证书 | 若服务器上已有 `*.example.com` 通配符证书，直接复用即可 |

**acme.sh + DNS-01 五步：**

```bash
# 1) 安装 acme.sh
curl https://get.acme.sh | sh -s email=you@example.com

# 2) 设置默认 CA 为 Let's Encrypt（acme.sh 默认零 SSL，建议显式指定）
~/.acme.sh/acme.sh --set-default-ca --server letsencrypt

# 3) 用 DNS API 签发（此处以阿里云 DNS 为例，需配置 RAM AccessKey 环境变量）
export Ali_Key="<AccessKeyId>"
export Ali_Secret="<AccessKeySecret>"
~/.acme.sh/acme.sh --issue --dns dns_ali -d api.example.com

# 4) 安装证书到 Nginx 目录（--reloadcmd 让续签后自动 reload）
sudo mkdir -p /etc/nginx/ssl
~/.acme.sh/acme.sh --install-cert -d api.example.com \
  --key-file       /etc/nginx/ssl/api.example.com.key \
  --fullchain-file /etc/nginx/ssl/api.example.com.pem \
  --reloadcmd      "sudo systemctl reload nginx"

# 5) 校验证书（确认链完整、域名匹配）
openssl x509 -in /etc/nginx/ssl/api.example.com.pem -noout -subject -dates
```

> acme.sh 会自动创建续签定时任务，无需额外配置 cron。

### 3.2 安装 Nginx 站点配置

复制模板并按你的域名与证书路径替换 **3 处占位**（`server_name`、`ssl_certificate`、`ssl_certificate_key`）：

```bash
sudo mkdir -p /etc/nginx/ssl
sudo sed \
  -e "s#api.example.com#api.example.com#g" \
  -e "s#/etc/nginx/ssl/api.example.com.pem#/etc/nginx/ssl/api.example.com.pem#g" \
  -e "s#/etc/nginx/ssl/api.example.com.key#/etc/nginx/ssl/api.example.com.key#g" \
  /opt/error-learn/deploy/nginx/error-learn.conf \
  | sudo tee /etc/nginx/conf.d/error-learn.conf >/dev/null

sudo nginx -t
sudo systemctl reload nginx
```

**HTTP/2 写法注意版本分支**：

- Nginx **≥ 1.25.1**：使用 `http2 on;`（模板默认写法）
- Ubuntu 24.04 apt 版（**1.24.0**）：必须改用 `listen 443 ssl http2;`，否则 `nginx -t` 报错

**证书替换后必须 `reload`** 才生效：

```bash
sudo systemctl reload nginx
```

### 3.3 与现有环境共存（服务器上已有 Nginx）

若 ECS 上已有 Nginx 且 80/443 被其它站点占用：

1. **复用现有 Nginx**，不要重装；本配置作为**新的独立 `server_name`（子域名）** 接入，互不影响；
2. 只执行 `reload`，**不要 `restart`**，避免中断其它站点；
3. 端口冲突处理：若已有 `default_server` 占用 80，请把 `/.well-known/acme-challenge/` 放到已有站点中或改用 DNS-01；
4. 运行用户差异：Debian/Ubuntu 通常为 `www-data`，CentOS/RHEL 为 `nginx` —— 同步调整 systemd 的 `User=` 与目录属主；
5. 复用通配符证书时，把三处占位指向已有证书路径即可。

### 3.4 外部连通性验证

```bash
curl https://api.example.com/api/v1/health     # 期望 {"status":"ok"}
```

## 4. 前端构建与发布（微信小程序）

### 4.1 配置生产 API 基址

`client/.env.production` 中把域名替换为真实子域名：

```
TARO_APP_API_BASE=https://api.example.com
```

> 若为空，[constants/index.ts](../../client/src/constants/index.ts) 会回退到开发用局域网 IP，真机将无法访问。

### 4.2 构建并上传

```bash
cd /opt/error-learn/client      # 或本地开发机
npm install
npm run build:weapp             # 产物在 client/dist/
```

在**微信开发者工具**中导入 `client/`（`miniprogramRoot` 指向 `dist/`），确认 AppID 为 `wx683110d829c1f0f9`，然后「上传」并提交审核。

## 5. 微信公众平台配置

### 5.1 服务器域名（开发 → 开发管理 → 开发设置 → 服务器域名）

同时配置 `request`、`uploadFile`、`downloadFile` 合法域名，均为 `https://api.example.com`。

**微信侧硬性要求：**

- 域名必须**已备案**；
- **不能带端口**；
- **不可**配置 `api.weixin.qq.com`；
- TLS **≥ 1.2**，且支持 **ECDHE** 系列加密套件。

### 5.2 用户隐私保护指引

路径：**设置 → 功能设置 → 用户隐私保护指引**。

- 按实际收集的信息填写（如头像、昵称、相册/摄像头用于题目拍摄）；
- **配置后需重新审核发布才生效**；
- 隐私相关接口的授权流程由前端 `PrivacySheet` + 隐私政策页承载，详见 `.trae/docs/increments/incr-20261015-上线合规改造/`。

## 6. 运维

### 6.1 更新发布

```bash
cd /opt/error-learn
git pull
cd server && ./.venv/bin/python -m pip install -r requirements.txt
sudo systemctl restart error-learn-api
```

前端重新 `npm run build:weapp` 并在微信后台「版本管理」发布。

### 6.2 证书到期巡检

```bash
openssl x509 -in /etc/nginx/ssl/api.example.com.pem -noout -enddate
```

用 acme.sh（DNS-01）签发可自动续签，无需人工干预；用控制台免费证书则需在 90 天内人工更换。

### 6.3 备份

- 应用侧：`UPLOADS_DIR`（头像等静态文件）建议定期打包异地备份；
- 数据库：在 **RDS 控制台**配置自动备份策略，无需应用脚本介入。

### 6.4 一键部署脚本

仓库提供 `deploy/deploy.sh`，可在 ECS 上一条命令完成「装依赖 → 装 systemd → 装 Nginx → 健康检查」：

```bash
sudo DEPLOY_DIR=/opt/error-learn DOMAIN=api.example.com bash /opt/error-learn/deploy/deploy.sh
```

> 脚本不代为申请证书，请先按第 3.1 节准备好证书。

## 7. 排障（按阿里云 RDS 官方错误码）

| 错误码 | 现象 | 处理 |
| --- | --- | --- |
| **2003** | `Can't connect to MySQL server` | 检查 RDS 白名单是否放行 ECS **内网 IP**；确认 ECS/RDS 同 VPC、连接串主机为内网地址 |
| **1045 (#28000)** | 认证失败 | 核对账号密码；确认该账号对 `error_learn` 库有权限 |
| **1045 Access denied** | 密码校验失败 | MySQL 8 使用 `caching_sha2_password`，需 `pip install "PyMySQL[rsa]"`（提供 cryptography） |
| **2059** | `Authentication plugin cannot be loaded` | 同上，缺少 `cryptography` 依赖；8.4 已移除 `mysql_native_password`，勿依赖旧插件 |
| **2006** | `MySQL server has gone away` | 连接空闲超时或包过大；检查连接池/超时设置，确认 Nginx `client_max_body_size` 足够 |

其它常见问题：

- **服务起不来**：`journalctl -u error-learn-api -n 50`；常见为 `.env` 缺 `JWT_SECRET`/`DATABASE_URL`。
- **Nginx 起不来**：`nginx -t` 定位；多为证书路径错误或 HTTP/2 写法与版本不符（见 3.2）。
- **小程序请求失败**：确认域名已备案、无端口、TLS 合规，且已在公众平台配置合法域名。
- **头像 404**：确认 `UPLOADS_DIR` 与 Nginx `/static/` alias 指向同一目录。
